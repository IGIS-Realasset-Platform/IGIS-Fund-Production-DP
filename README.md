# IGIS Development Project Platform

현재 v0.11.0은 기존 핵심 플랫폼 기능을 유지하는 배포 후보이며 미배포·새 계약 구현/재검수 중입니다. Notion은 선택 보충자료입니다. 자료 없음은 코어 배포 실패가 아니고 수기 사업 등록·전체 기능은 계속 정상이어야 합니다. 이전35버전과 초기 Notion 후보의 검수/대체 이력은 보존합니다.

최신 사용자 결정은 기존 프로젝트 안의 별도 비공개 데이터영역(schema) 사용과 개인 제작용 Hobby 유지입니다. 기존 조직 서비스와 연결하지 않는 준비 상태를 기록하며, 기존 제품 검증을 앱 연결·배포 완료로 확대하지 않습니다.

개발사업의 사업비·계약·인허가·개발업 등록정보를 관리하고 국토교통부 보고서를 작성하는 사내 업무 플랫폼입니다.

현재는 개인적으로 제작·검증 중인 로컬 HTML 검증본입니다. 회사 계정을 사용한다는 사실과 현재 제작 목적은 구별합니다. 중앙 데이터베이스 연결·직원 로그인·운영 배포가 완료된 서비스는 아닙니다.

최신 결정은 같은 프로젝트 안에서 기존 조직 서비스와 연결하지 않는 별도 비공개 데이터영역을 사용하는 것입니다. Supabase Table Editor 의 `Create a new schema`에서 `development_project_platform` 영역 1 개를 생성했습니다. 소유자는 관리 역할인 postgres 이며 새 영역의 테이블·함수·타입은 각각 0 개입니다.

schema 는 같은 DB 안에 마련하는 별도 공간입니다. 기존 조직 테이블이나 데이터 관계, 뷰·함수에 연결하지 않는 논리적 분리이며 별도의 DB 서버를 만든 것은 아닙니다. 서버 처리·저장 자원은 기존 프로젝트와 공유합니다. 따라서 독립 서버나 모든 영향이 없는 완전한 분리로 표현하지 않습니다.

새 영역은 PUBLIC 접근이 없고 anon/authenticated/service_role 의 USAGE·CREATE(영역 사용·생성) 권한도 없습니다. 세 앱 역할의 실제 접근에서 권한 거부(42501)를 확인했고 관리 역할로 복귀했습니다. 외부 요청용 Data API 설정에도 새 영역을 노출하지 않았습니다. 기존 노출 목록은 public/graphql_public 만 유지하며 설정 변경은 0 건입니다. 앱의 저장·로그인·권한 연결은 아직 구현 완료 상태가 아닙니다.

별도 schema 준비 검증에는 구조·권한 목록만 사용했고 기존 조직DB의 실제 직원·업무행 조회와 쓰기는 각각 0 건입니다. 이는 이번에 승인받아 읽은 Notion36사업/인력배치와 다른 범위입니다. 기존 보호 대상 구조 및 원격 변경이력은 전후 동일했습니다. 기존 서비스·참고 저장소 원장을 수정하지 않았고 신규 테이블·중앙DB 연결·자료 이관·배포도 각각 0 건입니다. 이 작업을 실제 업무자료 손실이나 기존 조직 서비스 장애로 판단하지 않습니다.

현재 개인 제작·검증 목적의 Vercel Hobby 를 유지합니다. 회사 계정 사용과 실제 사용 목적은 구별하며, 향후 직원 공동 사용·회사 운영으로 전환할 때 요금제 적합성을 별도로 검토합니다. 지금 유료 전환을 확정하지 않습니다. 현재 연결 도구의 선택 권한 범위에서 확인한 403 은 요금제 문제가 아닌 별도 접근 상태입니다. 기존 보호 설정도 실제 앱 배포·앱 인증 완료를 의미하지 않습니다. [Vercel Hobby 공식 기준](https://vercel.com/docs/plans/hobby)

## v0.11.0 핵심 기능 유지·선택 보충 배포 계약

### 최신 직접 정정 — 코어 배포·Notion 선택 보충

- 목표는 기존 웹 플랫폼의 모든 기능·UI·입력/저장/취소·사업비/금융/인허가/계약/등록/보고/출력을 유지하여 배포하는 것입니다. Notion 중심의 새 플랫폼 재구성이나 불필요한 자료 재연구를 하지 않습니다.
- Notion 자료가 없어도 빈 실제 플랫폼을 빌드·실행하고 수기로 사업을 등록/편집할 수 있어야 합니다. optional source는 available:false이며 예시4사업·가상 금액을 실제 원장에 섞지 않습니다.
- 정상 보충자료가 있을 때만 출처와 안정ID·필드 의미·비인명/미확인 기준을 적용합니다. invalid source는 addon 적용만 막고 사용자 수기 사업·값은 보존합니다.36사업/120배치 검수는 당시 보충 snapshot 이력이지 코어 필수 배포 수량이 아닙니다.
- optional api/notion-source의 서버 Secret 값은 클라이언트·Git·문서·로그에 넣지 않습니다. 없으면 코어 계속, 조회시점 snapshot 제공은 Notion API 실시간 연동이 아닙니다.
- 중앙DB 저장·직원 앱 로그인/서버권한은 미연동입니다. 원격 개발소스는 현재 미게시이고 Git 연결1개만 확인됐습니다. 게시/최종 보호 배포는 결과로 따로 확인하며 새 credential/광범위 OAuth 생성으로 범위를 확대하지 않습니다.
- PROD110-17~22로 최신 계약을 연결합니다. 초기16의 원본 필수·36/120 조건·원본 없는 빌드 실패는 대체됐으며 기존 전 기능·자료 보존·예시 분리·개인정보·새 최종 검수 기준은 유지합니다. 새로운 코어/선택 addon 검증 전 출시 완료로 표시하지 않습니다.

현재 준비된 코어는 추가자료 없이0사업으로 빌드되고 수기 사업 자동5/5·기존13기능 존재·optional API4·packaging4가 통과했습니다. Git 자동 CI는 committed deployment/approved-core.json의 승인 해시/버전을 사용할 수 있어 자료 Secret·DP_EXPECTED 환경값을 필수로 두지 않습니다. 출력 HTML은 Git에서 제외합니다. 과거 Source필수/36·120 후보 검수는 이력으로만 보존하며 현재 코어의 실제 화면·출력·최종 보호URL은 검수 대기입니다. 기본 MXC/Node/CUA 실행환경 오류는 제품 실패가 아닙니다. 원격 코드 미게시·자료 환경 Secret 미설정·배포0·Notion 실시간/중앙DB/Auth 미연동을 유지합니다.

### 초기 Notion 우선 후보 이력 — 일부 대체됨

아래 원본필수/고정수량/빌드 실패 절차는 최신 지시로 대체된 당시 기록입니다. 현재 코어의 배포 조건으로 적용하지 않습니다.

Notion MCP로 확인한36사업을 사용하고 기존 가상4사업은 실제 배포에서 제외합니다. 이름120배치와 고유 이름43문자열은 원본 배치 집계이며 실제 인원·법적 자격·이수·재직 확정이 아닙니다. 원본에 없는 비용·면적·일정·계약·등록·보고 상세는 빈값/빈 목록입니다. 원본 구분4상태를 자산용도·인허가 단계로 바꾸지 않습니다.

36사업의 개요4필드와120인력 배치는 같은 후보에서 실제 전수대조했습니다. 다만 전체 세부탭·3해상도·편집/실패/출력·최종 보호URL은 검수 중입니다. 아직 출시/배포 완료로 표시하지 않습니다.

이 문서와 함께 게시 대상으로 준비하는 것은 실자료 원문 없는 소스코드 목록(allowlist)입니다. 실제 snapshot은 Git에 넣지 않고 보호 프로젝트의 빌드 Secret `DP_NOTION_SNAPSHOT_JSON`으로 전달하는 staging 방식입니다. source code publication의 성공은 commit/push 결과로 확인하며 코드 게시를 앱 배포 완료로 표시하지 않습니다. 원본 입력이 없거나 잘못되면 빌드를 실패시키며 예시/합성자료로 대체하지 않습니다. Secret 값·원문을 로그에 출력하지 않습니다. 생성 HTML에는 실제 표시자료가 포함되므로 Git에서 제외하고 최종 URL·자산의 접근 보호를 실제 확인합니다. Secret 설정·클라우드 빌드·preview36 fixture proof·최종 배포는 아직 확인 완료가 아닙니다.

현재 자료는 조회시점 snapshot이며 Runtime Notion API 자동 동기화·중앙DB 저장·직원 앱 로그인/서버권한은 미연동입니다. Git 연결1개·보호 설정을 앱 자동연동/저장/배포 완료와 구별합니다. MCP403/팀목록0은 별도 도구 접근 상태입니다. 개인 제작 목적의 Hobby 유지 기준은 바꾸지 않습니다.
