# IGIS 개발사업관리플랫폼

개발사업의 사업비·계약·자금조달·인허가·보고자료를 프로젝트별로 모아 관리하는 웹 플랫폼입니다.
운용 담당자와 개발솔루션센터가 같은 기준으로 현재 상황과 변경 이력을 확인할 수 있도록 만듭니다.

회사 운영 전환이나 전체 요구사항 완료를 선언한 버전은 아닙니다.
현재 정식 C53의 범위는 [PUR125 검수](docs/purpose-20261023-verification.md)를 확인합니다. C53은195개 회귀묶음, 격리 업무80개·법령 실패조건2개·기본 화면120개와9프리셋 Excel54개를 확인했습니다. C52에서 발견한 중간행 아래 상세23개 누락은 C53에서 교정했으며 전체 기능 수락으로 확대하지 않습니다. 이번 [REVIEW126 명세](docs/review-20261026-spec.md)와 [구성요소 매트릭스](docs/component-review-matrix.md)는 별도 검토입니다.
현재 검수 결과와 남은 조건은 [통합 검수](docs/followup-20261022-verification.md), [기존 수정대장](docs/center-20261020-fix-ledger.json), [최신 UI 요구](docs/ux-20261022-spec.md)에서 구분합니다. 가상 A·B·C 보완자료는 전용 중앙 DB에 반영했으며, 실제 로그인한 소유자의 하위 비용 1원 수정·저장·새로고침·원금액 복원을 확인했습니다. 다른 모든 회원과 모든 하위 버튼의 실검수 완료를 뜻하지는 않습니다.

v0.12.2에서는 비용의 설명용 정보창을 없애고 본표에서 필요한 관리로 직접 연결합니다. 법령 상세는 실제 변경 전·후와 정확한 공식 비교/원문을 바로 보여주며, 법령명·공포일·시행일은 표 제목을 눌러 정렬합니다. [최신 UI 검수](docs/ux-20261022-verification.md)에 정식 파일·실제 로그인 화면과 범위별 증거를 기록합니다. 내장 명세의 상태는 빌드 시점 스냅샷이며 정식 반영 이후의 최신 결과는 이 문서를 우선합니다.

v0.12.3은 [AUTO123 명세](docs/recheck-20261022-spec.md)와 [자동화·전체 요청 재검토](docs/recheck-20261022-verification.md)를 확인합니다. 상세를 열 때 공식 비교자료를 자동 조회하며, 전체 법령의 비교문을 매일 미리 생성·저장하는 기능은 아닙니다. 공식 자료 미제공과 일시적인 통신 실패를 구별하고 확인한 원문을 제공합니다. 일일 수집의 부분 실패와 모든 역할·하위 조건의 미검증 범위는 별도로 남깁니다. 최종166개 회귀묶음과 격리 PC/모바일 법령14·시장8흐름 통과, 정식 파일 지문 일치·익명 API 차단·기존 검증주소 보호를 확인했습니다. 소스 커밋은 `fda53a7c4f1febc62ac6a04edbcb38c3663888f8`이며 이후 문서 전용 갱신과 구별합니다.

## 이번 검토의 범위

인허가 상세는 조회와 수정을 구분하고 개요·신청/심의 기록·검토의견/조치·법령/조건을 한 창에서 확인하도록 교정합니다. 메뉴는 글자 목록과 완전 숨김을 유지합니다. DB 구조·권한·저장 이력을 그대로 두고 조회 코드만 최적화합니다.

‘전체 법령’은 전국 모든 법규라는 뜻이 아닙니다. 2026-10-26 실제 일일 대상194개 중 자치법규10개(서울5·경기1·고양2·용인2)이며 사업별 명시 구독은0개였습니다. 공식 검색·등록·일일 확인·추천 근거·사업별 연결을 구별합니다. [5개 요구와 검토 상태](docs/review-20261026-spec.md)를 확인해 주세요.

## 만든 목적

개발사업에서는 초기 투자검토, PF, 도급계약, 설계변경, 준공 단계마다 관리해야 하는 정보가 달라집니다.
여러 엑셀·계약서·공유폴더에 흩어진 정보를 연결해 다음 업무를 돕는 것이 목적입니다.

- **사업비 변경 통제:** 최초 언더라이팅·승인 기준·현재 준공추정원가를 비교하고 증감 사유를 추적합니다.
- **인허가 누락 방지:** 사업유형과 조건에 따른 절차, 일정, 검토의견과 조치계획을 함께 확인합니다.
- **자료와 보고의 연결:** 계약·원본 경로·변경 이력을 연결하고 국토부 보고서 작성에 활용합니다.

회사의 사업비 관리 수준과 기존 재무모델을 우선합니다.
CBS는 비용을 공통 코드로 분류하는 기준이며, 모든 비용을 처음부터 과도하게 세분화하는 목적은 아닙니다.

## 처음 사용하는 방법

1. [플랫폼](https://igis-development-project-platform.vercel.app/)에 접속합니다.
2. 허용된 회사 이메일로 회원가입하고 **8~15자 비밀번호**를 설정합니다.
3. 가입 메일로 받은 6자리 번호를 화면에 입력해 이메일을 확인합니다.
4. 이후에는 이메일·비밀번호로 로그인합니다. 필요하면 `로그인 상태 유지(7일)`를 선택합니다.
5. 프로젝트 현황에서 A·B·C 중 하나를 열고, 왼쪽 메뉴에서 업무를 선택합니다.

일반 로그인은 기본 8시간, 유지 옵션은 선택한 브라우저에서 7일의 고정 만료시간을 사용합니다.
로그아웃하면 해당 로그인 상태가 해제됩니다. 브라우저에 비밀번호를 평문으로 저장하지 않습니다.

현재 A·B·C는 화면과 기능을 확인하기 위한 샘플입니다.
가상 인물·샘플 경로는 실제 직원 자격이나 실제 존재하는 파일을 의미하지 않습니다.

## 주요 사용 방법

### 사업비 입력과 비교

1. 프로젝트를 선택한 뒤 `원가 관리 → 세부 사업비`를 엽니다.
2. `항목 선택·추가`에서 필요한 관리항목을 선택합니다.
3. 용도별 항목 묶음이 필요하면 `사업비 프리셋`에서 현재 항목과 추가 후보를 확인하고 적용합니다.
4. 수정할 **금액 셀을 더블클릭**합니다. 원 단위 정수로 입력하고 Enter로 저장하거나 Escape로 취소합니다.
5. 비교 기준을 선택해 최초 기준과 현재 예상원가의 차이를 확인합니다.
6. `이력`에서 전후 금액과 관련 변경을 확인하고, 필요하면 엑셀로 내려받습니다.

| 항목 | 사용 기준 |
| --- | --- |
| 금액 입력·저장 | 1원 단위 정수 |
| 표의 금액 표시 | 백만원 단위 정수. 비교 증감액도 같은 단위 |
| 미입력과 0원 | 미입력은 금액 미확보, 0원은 사용자가 확인한 값으로 구분 |
| 용도별 프리셋 | 복합개발·오피스·리테일·호텔·물류·데이터센터·시니어리빙·임대주택·분양주택 |
| 프리셋 금액 | 금액 샘플이 아니라 빈 관리항목 묶음. 기존 금액을 초기화하지 않음 |
| 엑셀 | 화면의 분류명·항목명·순서·단위를 유지하는 사업비표 한 시트 |

분기말에는 확인 과제가 생성되고, 담당자가 내용을 확인해 저장해야 해당 시점의 고정본이 생깁니다.
PF·리파이낸싱·도급 변경 같은 주요시점 기록은 별도로 남길 수 있습니다.
정기 기록이 승인예산을 자동으로 바꾸지는 않습니다.

모든 비용의 선택적 하위 분해·직접 세부내역 추가·신규비용 이력은 v0.12.1에 정식 반영됐으며 v0.12.2에서도 유지합니다.
현재 게시 기능과 혼동하지 않도록 버전 이력에서 구분합니다.

v0.12.1에서는 항목을 펼쳐 `하위 항목 추가`로 필요한 내역만 기록할 수 있습니다. 기존 유형을 선택하거나 해당 유형 아래 계약·내역명을 직접 적습니다. 금액이 있는 항목을 처음 나눌 때는 입력한 하위 합계가 원래 금액과 일치하는지 확인하고 전환합니다. 이후 하위 금액을 수정하면 상위는 합계로 계산되며, 원금액을 임의로 나누거나 상위·하위를 두 번 합산하지 않습니다.

### 인허가와 조치계획

1. `인허가·사업관리`에서 사업유형·사업방식·지역·규모 등 조건을 확인합니다.
2. 인허가 추천과 전체 목록에서 필요한 절차를 선택해 추가합니다.
3. 각 절차를 열어 계획일·실제 신청/보완/승인, 담당기관과 근거자료 경로를 입력합니다.
4. 검토의견마다 **무엇을 어떻게 조치할지**, 담당자·기한·자료를 기록합니다.
5. 목록 또는 일정 맵에서 절차의 선후관계와 진행상황을 확인합니다.

추천은 누락 방지를 위한 검토 후보입니다.
지역 조례, 의제·통합심의, 변경허가 등 실제 적용 여부는 해당 사업의 자료와 법령을 확인해야 합니다.
아직 발생하지 않은 실제 날짜를 완료한 것처럼 입력하지 않습니다.

| 개발업 등록 | 등록정보 입력/수정 후 법인·등록번호·등록일·관할기관·증빙 경로 기록 |
| 전문인력 | v0.12.5 후보: 이름·소속·교육일·확인한 연수교육 이수기한·재직을 관리. 퇴사 처리와 복구는 명단에서 실행 |

폴더 경로 클릭으로 Windows 탐색기를 여는 동작은 회사의 브라우저 정책과 PC 환경에 따라 제한됩니다.
도우미 설치나 회사 정책 변경은 현재 적용하지 않았습니다.

### 대출 조건과 변경 관리 (v0.12.5)

1. `파이낸싱`에서 대주별 약정액·누적 실행액·잔액과 금리·수수료·만기를 확인합니다.
2. 금융기관명을 누르면 해당 대출의 금리조건·상환·담보·변경 전후와 사유를 한 화면에서 봅니다.
3. `대출 정보 수정`에서 금리, 선취·취급 수수료, 금융자문 수수료, 약정 ALL-IN을 각각 입력합니다. 본표의 같은 셀에서도 수정할 수 있습니다.
4. `ALL-IN 기준`은 그 대출 약정에 따라 금융자문수수료 **포함/제외**를 선택합니다. 기존 ALL-IN을 임의로 역산하거나 모든 수수료율을 단순히 더하지 않습니다.
5. `분기 기준값 기록`으로 당시 조건을 남깁니다. 과거 기록에 현재 금리·수수료를 끌어와 채우지 않습니다.

미입력은 0%가 아닙니다. 금리가 빠졌거나 포함 기준이 다른 대출은 가중평균을 확정값처럼 표시하지 않습니다.
LTV/LTC는 확인한 입력값이며, 플랫폼이 자산가치나 금융약정 위반을 자동 판정한 수치가 아닙니다.
약정액과 잔액이 모두 확인된 0원인 대출만 삭제할 수 있고, 삭제 직전 바뀐 대상은 다시 확인합니다.

### 보고서 작성·저장·출력

1. `국토부 보고서`에서 작성할 양식과 기준일을 선택합니다.
2. 미리보기에서 필요한 셀을 수정합니다.
3. 저장할 때 `보고서에만 저장` 또는 `플랫폼에도 반영`을 선택합니다.
4. 플랫폼 반영은 연결이 명확한 값만 대상으로 하며, 저장 전 변경 내용을 확인합니다.
5. 작성본을 확인한 뒤 인쇄하거나 PDF로 저장합니다.

보고서의 제목·합계·복합 문구를 바꿨다고 플랫폼 원장이 역산되지는 않습니다.
과거 저장본과 확정 원본은 유지하며, 정정은 새 버전으로 남깁니다.
보고서 생성은 정부 시스템에 실제 제출하거나 수리받는 기능이 아닙니다.

### 알림·업체자료·법령 확인

- **알림:** 왼쪽 하단에서 목록·상세를 열고 대상 업무로 이동합니다. 삭제는 본인 목록에만 적용됩니다.
- **업체자료:** 출처와 기준일을 먼저 확인합니다. 미제공·조회 실패·미확인 신용 후보를 확인된 0이나 대표등급으로 보지 않습니다.
- **법령:** 변경 목록에서 법령명을 눌러 개정문·전후 조문·공식 자료를 확인하고, 공포일·시행일·법령명 제목으로 정렬합니다. 사업별 법령과 실제 담당자 검토는 별도로 유지합니다.

v0.12.4부터 별도 `상세 보기` 도구 열 없이 법령명에서 실제 변경 전·후와 공식 신구조문/원문을 바로 엽니다. 수집 확인 상태·확인 이력·운영 재시도는 업무 화면에 노출하지 않으며 운영 기록은 앱 전용 DB에 보관합니다. 근거 없는 전체 프로젝트 목록·빈 검토표는 만들지 않으며 실제 담당자 검토기록은 보존합니다.
법령 변경이 프로젝트 일정·진행상태·조치계획을 자동으로 바꾸지는 않습니다.

## 개발환경과 테스트

Node.js 24와 저장소의 잠금파일을 기준으로 합니다.

```powershell
npm ci --ignore-scripts

# 외부 서비스나 실제 DB 없이 실행하는 대표 검사
node tests/cloud-storage.mjs
node tests/center120-law-api.mjs
```

위 두 검사는 GitHub 추적파일만 추출한 깨끗한 환경에서 실제 실행했습니다(22개·9개 통과). 실제 DB·메일·법제처 연결 검수가 아니라, 합성 입력으로 공통 동작을 확인하는 검사입니다.

전체 기능 검사는 아래 명령이 기준이지만, **GitHub만 내려받은 환경에서는 아직 전부 재현할 수 없습니다.** 일부 검사는 미동봉 시험자료·생성 HTML·외부 참조 판본이 필요합니다. 기존 선택기에 빠졌던 회사 양식 검사는 이번 소스에 함께 게시하며, 자료가 없는 검사를 임의의 빈값으로 통과시키지 않습니다.

```powershell
node scripts/verify-center120.mjs
```

`center120-cost.mjs` 등 기본 원가 검사는 비공개 시험자료인 `src/data/legacy-seed.json`이 필요합니다. 회사 원본을 GitHub에 올리는 방식으로 해결하지 않습니다. 필요한 검사와 준비조건은 [개발 가이드](docs/DEVELOPMENT.md)에서 구분합니다.

실제 브라우저 검사에는 설치된 Edge와 승인된 격리 자료·참조 스냅샷이 필요합니다.
검수기 소스가 있다는 사실만으로 모든 PC에서 바로 재현되거나 실제 회원 검수가 끝난 것은 아닙니다.

`npm run build`는 Vercel의 승인된 환경·브랜치·서버 설정에서 실행하는 배포 빌드입니다.
일반 PC의 `npm start` 명령이나 로컬 파일 더블클릭 방식은 제공하지 않습니다.
사용자는 위 플랫폼 주소에 접속하며, 개발자는 비밀값 없이 실행 가능한 검사와 실제 연결 검수를 구분합니다.

## 배포·보안 원칙

1. 승인된 기능을 수정하고 실패검사·회귀검사를 실행합니다.
2. 정확한 최종 HTML로 실제 화면·저장·출력을 확인합니다.
3. 검수 완료 소스와 문서를 GitHub 기본 브랜치에 동기화합니다.
4. 정식용 후보를 빌드하고 파일 지문·로그인 보호·API·로그를 확인합니다.
5. 확인한 후보만 정식 주소로 승격합니다.

기본 `main`의 문서 갱신은 자동 정식 배포를 하지 않습니다.
기존 검증 브랜치 `preview/core-v0.11.0`와 별도 승격 경로를 유지합니다.

- 서버에서 이메일 허용목록·세션·사업별 권한을 재검사합니다.
- 브라우저에 DB 비밀번호·메일 비밀번호·API 인증값을 넣지 않습니다.
- 기존 서비스·공유 Auth·다른 스키마는 변경하지 않습니다.
- 비밀번호·토큰·실제 업무자료를 GitHub 이슈나 문서에 붙이지 않습니다.
