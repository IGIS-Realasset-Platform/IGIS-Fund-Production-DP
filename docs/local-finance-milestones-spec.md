# LOCAL-UI-155 사업 단계별 변화 추적

- LOCAL-UI-154의 최초/현재 비교를 직전 사업 단계 비교로 대체한다. 단계 선택은 하나이며 원가·조달·기간·면적·변경 사유 모두 같은 시점을 사용한다.
- 최근 단계는 사용자가 지정한 이름·기준일·이슈를 저장하고 원가와 조달은 현재 원장에 연결한다. 과거 미확보값을 현재값으로 채우지 않는다.
- 중간 단계 추가는 세부사업비의 비교시점 입력을 재사용한다. 원가와 금융 보조지표를 같은 workspace에 단일 저장한다. 정정본의 원금액과 과거본을 보존한다.
- 승인된 서울 중구 검토용 표시: 최초 언더라이팅 → 1차 리파이낸싱 → 본PF 1차. 가상 중간금액만 로컬 비교시점으로 추가한다. 최초/현재 원금액·계약·대출·출자를 바꾸지 않는다.
- 최근 단계 수정, 단계 추가/정정, 취소/Escape, 저장 실패/충돌, 프로젝트 격리, 새로고침, 직전 증감, 0/미입력을 검사한다. 이전 SQLite 기록의 조회/편집 경로를 보존한다.
- 운영 DB·배포 변경 없이 로컬 커밋까지만 수행한다. 구현/자동검사/실제화면 검수를 구별한다.

## LOCAL-UI-158 선택 단계별 조달구조

하단 구조는 상단 선택 단계와 같은 자료만 사용한다. 최초/리파이낸싱은 당시 투자자·트랜치·출자/약정액의 별도 저장본, 최근 본PF는 로컬 현행 대출·출자 원장을 읽는다. 과거 기록에 구조가 없으면 현재 구조를 대신 표시하지 않는다. 원가·기성·지급을 조달로 혼합하지 않는다. 단계 조달 총액은 해당 자금 제공자 금액 합계와 같아야 한다. 변경된 현재 원장이 과거 구조로 전파되면 실패다. 마우스 강조/키보드 선택/조달 내역 보기/단계 정정/현재 대출 수정도 선택한 단계 문맥을 따른다.

사용자 지시에 따라 로컬 더미의 자금 흐름을 브릿지 → 리파이낸싱 → 본PF의 순차 시나리오로 정리한다. 초기 출자600억+브릿지1,500억=2,100억, 리파 출자900억+선순위1,500억+후순위400억=2,800억, 본PF 출자1,100억+선순위1,950억=3,050억. 당초 제가 만든 별도 최초 조달 예시3,050억/중간3,120억을 그대로 존치하지 않고 이를 대체한다. 최초 원가5,123억·최근 원가5,163.8억은 불변이다. 로컬 현행 A은행 브릿지 분류는 본PF 단계의 약정으로 정리하고 앞선 브릿지/리파 자금 제공자는 과거 단계에 따로 보관한다. 운영 DB·원본 복사파일은 변경하지 않는다. 원가자료와 원금액·기성/지급 이력은 보존한다.
