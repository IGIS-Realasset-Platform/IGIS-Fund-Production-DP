# REVIEW132 사업비 계층의 안전한 저장 경계

2026-10-30. 독립 검토 후보 `qa132-cbs-graph-depth`를 현재 소스와 격리자료로 검증했습니다. 원금액·원자료·회사 분류를 변경하지 않았습니다.

## 확인한 결함

기존 JSON 중첩깊이100 검사는 `parentId`가 만드는 평탄 배열의 관계 깊이를 제한하지 않았습니다. 현재 편집자 workspace PUT에 590,321바이트(4MB 이하)·12,000단계의 비순환 CBS를 보내면200 저장, GET200으로 재조회됐고, 저장된 상태를 현재 `src/cbs.js`의 `A.totalInfo`에 주입하면 `RangeError: Maximum call stack size exceeded`가 발생했습니다. 초기화의 회사 원가표 소비자도 이 합계 함수를 호출합니다. 실제 운영 사업을 변경하거나 외부 공격을 실행한 검증은 아닙니다.

## 최소 교정

`shared/cost-graph-safety.mjs`의 반복형 탐색은 신규/변경된 `parentId` 관계가 속한 연결범위(조상과 자손)에만 기존 JSON 안전깊이와 동일한100단계 및 순환 여부를 검사합니다. 노드 수의 임의 상한은 두지 않습니다. 현재 CBS와 신규/변경 과거 `costStages[].nodes`를 같은 정의로 처리합니다. workspace PUT은 병합 및 재귀 금액검증 전에 이 경계를 통과해야 합니다. 위반은422 `INVALID_COST_GRAPH`이며 원장·감사·재시도 저장이 모두 발생하지 않습니다.

이 검사는 분류를 새로 정하거나 금액을 배분하지 않습니다. 순서·명칭·금액만 바뀌고 관계가 같다면 기존의 모호한 부모·깊은 역사 구조를 임의수정하거나 관련 없는 저장을 차단하지 않습니다. 변경되지 않은 깊은 레거시가 새로 안전해졌다고 주장하지 않습니다.

## 독립 반례와 현재 자료 관측

`tests/review132-cbs-graph-depth.mjs`는 현재 실제 workspace handler·GET과 현재 CBS 계산 소비자에 독립 합성자료를 주입합니다. 유효 RED4통과/2실패에서 초기 교정 후6개 통과, 추가 독립범위 반례7통과/1실패를 확인한 뒤 현재8개 모두 통과했습니다.

- 12,000단계·590KB 입력의 저장전 차단 및 원장/감사/요청 불변.
- 정상100단계 허용, 101단계·순환의 현재/신규과거 저장 차단.
- 같은깊이의12,000형제 허용: 깊이 경계를 자료행 수 제한으로 바꾸지 않음.
- 같은 범위의1,000,001원 소계/상세, 독립2,000,000원, 명시0원과 미입력, 현재·과거 원자료 보존.
- 변경하지 않은 기존 모호한 부모·101단계 역사 구조의 관련 없는 저장 보존.
- 기존 깊은 레거시와 연결되지 않은 새 독립범위 허용, 상위 새연결로 기존 자손의 깊이가101을 넘는 반례 차단.

실제 앱 원장을 읽기전용으로 집계한 결과 현재 활성 CBS671개·관측 최대깊이4·순환false·101단계 도달false였습니다. 이름·금액·직원 정보를 반환하지 않았고 운영쓰기는0건입니다. 이 집계는 현재 CBS의 해당 속성만 확인한 것이며 과거 모든 파일이나 모든 관계의 전수 검증은 아닙니다.

정확 RED/GREEN 소스지문·실행결과는 `.build/review132-backend/cbs-graph-valid-red.json`, `cbs-graph-independent-red.json`, `cbs-graph-final-green.json`에 보존했습니다. 초기 합계 반례는 신규 금액에 필요한 기존 비용코드 계약이 빠져400으로 거절된 준비 오류였으며, 기존 원금액 원본을 준비해 동일 계층 소비자로 대조한 유효 RED와 구별합니다. 정식 배포 및 실제 브라우저 결과는 루트 통합검수에 연결하며 이 문서로 완료 승계하지 않습니다.
