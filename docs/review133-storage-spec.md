# C100 원천 사건 보존과 저장 크기

2026-11-02. C99 정상 수집 중 기존 32MiB 참조판본 상한에 도달했습니다. 실패 판본은 삽입되지 않았고 직전 판본과 이전 판본은 실제 존재합니다. 이 문서는 저장 중복을 줄이는 승인된 최적화 범위이며 자료 삭제·금액 변경·상한의 임의 증액·UI 재설계를 허용하지 않습니다.

| 요구 | 성공 기준 | 보존·실패 경계 |
|---|---|---|
| C100-01 | 기존 전역 원천 사건을 실제 불변 판본의 정확한 경로로 보존하고 새 사건과 구분해 저장합니다. | 기존 판본 수정/삭제0. 원사건의 모든 필드·ID·미입력/0·원문 금액을 보존합니다. |
| C100-02 | 과거 사건을 참조로 보존한 뒤에도 재수집의 같은 사건·충돌·정정·완료집합 검사를 수행합니다. | UI 미사용을 삭제 근거로 삼지 않습니다. 누락·충돌을 빈 배열·미확정 정상값으로 숨기지 않습니다. |
| C100-03 | 저장할 최신 판본은 기존 32MiB 상한 안에서 같은 의미를 유지합니다. 작은 기존 자료는 호환됩니다. | 새 사건까지 참조했다고 꾸미지 않습니다. 실제 저장 원본이 없는 참조·임의 중복 제거·잔액 배분0입니다. |
| C100-04 | 참조의 종류·고정 경로·판본·순서·건수·원문 일치·이력 보존을 검증합니다. | 임의 경로·앞선 판본·저장된 자기참조·순환·누락·변조·이력 절삭은 실패하고 이전 자료를 유지합니다. 유한 자원 한도를 명시합니다. |
| C100-05 | 수집→합치기→검증→불변 저장→다음 실행의 참조 읽기를 연결합니다. | 실패 시 업무 원장·금융 원값·권한·직원 원본·이전 참조판본을 일부만 변경하지 않습니다. |
| C100-06 | 회사별 계약·수주·단가·과거 발표 DTO와 화면 파일의 기존 의미를 보존합니다. | 전역 서버 사건과 회사별 조회 자료를 구별합니다. 원문 사건의 보존을 이유로 단가 확정이나 회사 추정 연결을 만들지 않습니다. |
| C100-07 | 독립 기대값의 실패검사·연결 회귀·현재 소스 전체검사와 실제 저장/재진입을 구분해 검증합니다. | 합성 크기 반례를 실제 직전 자료의 필드별 용량 측정으로 확대하지 않습니다. 정식 보안 보고·전체 플랫폼 수락은 별도입니다. |

전역 `automation.publicContracts`는 재수집의 기존 사건 검사에 쓰이고 현재 브라우저 반환 자료와 구별됩니다. 회사별 `source_contracts`·`recent_awards`와 단가 자료는 조회 소비자이므로 같은 판본의 DTO를 유지합니다. 완료창의 `records`는 정수 건수이며 원문 배열 중복으로 오인하지 않습니다. 원인 분석·구현·자동검사·실제 저장·추가 과거수집의 상태는 별도로 기록합니다.

변경하지 않는 범위는 UI/UX, 기존 입력·수정 규칙, 인허가, 프로젝트·금융 원장, 담당자·접속정책, 직원 원본, 기존 원천 발표와 보안 스캔 동결본입니다. 새 자료의 보관 방식은 기존 불변 참조 저장소 안에서 검증하며 별도 외부 서비스·키·스케줄을 만들지 않습니다.
