# 로컬 디자인 작업실

목적: 운영 사이트에 연결하지 않고, 원본 사이트에서 읽어 온 A·B·C 워크스페이스 복사본으로 둘러보고 수정한다. 운영 빌드·로그인 정책·업무 화면은 변경하지 않는다.

- LOCAL-01: 루프백 주소에서만 열리며, 브라우저의 외부 요청과 교차 출처 쓰기를 제한한다. 서버의 이오타 공용 주소록 조회는 LOCAL-UI-82의 회사·기관명, 담당자명, 분류에 한정한다.
- LOCAL-02: 새 환경에서 원본 A·B·C 복사본을 선택하고 기존 메뉴를 탐색한다. 지원되는 사업 수정은 로컬 파일에만 저장되고 새로고침·재시작 뒤에도 남는다. 오래된 탭의 저장은 새 자료를 덮지 않는다.
- LOCAL-03: 2026-11-10 승인에 따라 전체 메뉴·하위탭·팝업에 공통 디자인을 적용한다. 왼쪽 메뉴 폭·아이콘·간격도 참고 사이트 기준을 따른다. 상단 비교바와 제거한 통계박스는 표시하지 않는다. 디자인은 기존 사업 데이터나 도메인 계산을 변경하지 않는다. 적용·검수 상태는 [공통 디자인 명세](local-design-system.md)의 LOCAL-UI-01~08을 따른다.

## 사용법

1. 이 Mac에서 [로컬 작업실](http://127.0.0.1:4178/)을 엽니다. 회사 로그인은 필요하지 않습니다.
2. 화면 위의 사업 선택 목록에서 원본 사업 **A, B, C**를 선택합니다. 왼쪽 메뉴로 현황·사업비·자금·인허가·보고서 등을 둘러볼 수 있습니다.
3. 바로 열기: [프로젝트 현황](http://127.0.0.1:4178/?screen=portfolio) · [세부 사업비](http://127.0.0.1:4178/?screen=cost-detail) · [인허가·심의](http://127.0.0.1:4178/?screen=permits). 브라우저의 다른 탭에 운영 주소를 열면 두 디자인을 비교할 수 있습니다.
4. 사업 내용을 바꾸려면 기존 화면의 **수정**과 **저장**을 사용합니다. 사업 데이터는 저장소의 비공개 로컬 경로 `.build/local-preview/edits-<원본 지문>.json`에만 저장됩니다.
5. 계약 집행을 둘러보려면 상단에서 **샘플 · 기성·지급 검증**을 선택합니다. [원가현황](http://127.0.0.1:4178/?screen=cost-overview)의 계약·집행 요약과 **계약·문서 → 샘플 설계용역 계약 → 대금·지급**의 원장을 확인할 수 있습니다.

## 다시 실행하거나 직접 고치기

Node.js 24가 있는 환경에서 이 프로젝트 폴더를 열어 `npm run dev:local`을 실행합니다. 이 Mac에서는 `/usr/local/bin/node scripts/local-preview/server.mjs`로도 실행할 수 있습니다. 서버를 종료하면 주소도 닫힙니다.

- 로컬 공통 스타일은 `scripts/local-preview/design.css`에 있고, 화면별 스타일과 표시 로직은 같은 폴더의 portfolio, cost-detail, permits 파일에 있습니다. 새로고침하면 반영됩니다.
- 기능 실험: 해당 기능의 `src/` 파일을 편집하고 페이지를 새로고침합니다. 작업실이 앱을 다시 빌드합니다. 추후 공유하거나 배포하는 일은 별도 단계입니다.
- 기준 데이터는 로그인된 원본 서비스의 `GET /api/workspace` 응답 중 `state`입니다. 2026-11-04 복사 당시 서버 revision 59의 A, B, C를 그대로 보관합니다. `.build/local-preview/original-workspace.json`은 Git·배포에서 제외되며, 작업실은 이 파일을 읽기만 합니다. 파일이 없으면 실행을 중단합니다. 로컬 변경을 되돌리려면 서버를 종료하고 현재 원본 지문에 해당하는 edits 파일만 다른 이름으로 옮긴 뒤 다시 시작합니다.
- 격리 검사: `node tests/local-design-preview.mjs`는 임시 폴더와 임시 포트를 사용합니다. 사용자의 원본 복사본과 저장자료는 변경하지 않습니다.
- [논의·협업 Feed](http://127.0.0.1:4178/?screen=feed)는 원본 실무 게시판 코드를 재사용합니다. 이 Mac의 생성 파일은 `.build/local-preview/work-feed/`에 있습니다. 재빌드할 때는 `node scripts/local-preview/feed/build.mjs "/Users/jkjeon2025/Documents/GitHub/IGIS Fund Production DP"`를 실행합니다. 게시글 복사본은 Git에서 제외되는 `.build/local-preview/work-feed-seed.mjs`에 있으며, 변경사항은 작업실 주소의 브라우저 저장소에 보관합니다.
- 피드의 회사·기관명과 담당자명은 서버가 이오타 공용 주소록에서 조회합니다. 이오타 저장소의 `.env.local`을 사용하며, 저장소 경로가 다르면 실행 환경의 `LOCAL_IOTA_ENV_FILE`로 지정합니다.

## 재현 범위

사업·사업비·일정·인허가 등 워크스페이스에 포함된 데이터는 원본 복사본을 사용합니다. 원본 서비스에 별도 보관되는 자료는 이번 워크스페이스 복사 범위 밖입니다. 회사 로그인, 실제 직원·법령·Notion 조회, 메일, 외부 링크, 서버 전용 보고서 보관·권한 변경은 연결되지 않습니다. 보조 조회는 원본 상태에 있는 자료만 사용하고, 지원하지 않는 요청은 오류로 끝납니다. 실제 가입·권한·운영 저장을 검증하는 환경이 아닙니다.

사이드바의 ‘플랫폼 명세’는 원본 화면을 사용합니다. 바로 아래 ‘권한 관리’에는 C106의 회원별·조직별·프로젝트 담당 표를 읽기 전용으로 표시합니다. 첨부에서 옮긴 회원별 자료는 로컬 비공개 파일을 사용하며, 자료 파일이 없는 작업실에서는 미확보 메시지를 표시합니다.

시공사·협력사는 운영에서 확인한 2026-10-20 판본의 비공개 복사본 `.build/local-preview/partners-reference.json`을 읽습니다. 순위표·업체 상세·공사비 지표와 기준자료에 들어 있던 보관 댓글을 조회할 수 있습니다. 운영 자료 갱신과 실시간 댓글은 운영 화면에서 처리합니다.

시장 공사비는 별도 로컬 참고 파일 `.build/local-preview/market-reference.json`에서 2026년 9월 공식 통계표를 읽습니다. 파일이 없는 환경에서는 기존 복사본의 건설공사비지수를 사용합니다. 공식 자료는 [한국건설기술연구원 게시물](https://cost.kict.re.kr/notice/file/detail/47498)에서 확인할 수 있습니다.

## 검증 경계

원본 사업과 격리 회귀검사용 자료는 구분합니다. `tests/local-design-screens.mjs`는 별도의 임시 서버와 브라우저로 화면 회귀를 검사합니다. 로컬에 설치된 Playwright와 Chromium을 사용하며 필요하면 `PLAYWRIGHT_MODULE`과 `CHROMIUM_EXECUTABLE`로 경로를 지정합니다.

## LOCAL-UI-154 파이낸싱 개발단계와 조달 구조

- 이오타 `VehicleIntegrated.jsx`와 `IotaOne427DetailCard.jsx`를 기준으로 대출현황 위 흰색 영역에 사업 규모 금액과 지표 선택, 조달가·원가·토지가 카드, 사업 정보 및 2×2 비교 카드를 배치합니다. 단계 선택은 요청에 따라 최상단 가로줄에 둡니다. 브랜드와 타 사업 펀드 카드는 제외합니다.
- 세부사업비에서 ‘비교 기준 추가’로 저장한 시점을 상단 버튼에 표시합니다. 최초 언더라이팅과 선택 시점 또는 현재 준공추정원가를 비교합니다. ‘핵심 지표 보기’에는 원가관리 비교 기준과 별도 단계 기록의 전체 열을 표시하고 선택 열을 강조합니다. 저장된 변경 사유는 상세 표에서 표시합니다.
- 단계명·기준일·금액·사유는 프로젝트별 로컬 SQLite에 저장합니다. 샘플은 예시로 표시합니다. 등록·수정·삭제 후 새로고침과 프로젝트 전환에서 저장을 확인합니다. 취소와 저장 충돌에서 기존 기록을 보호합니다.
- 상단 총 조달규모는 하단과 같은 현재 대출 약정액·출자액 합계를 사용합니다. 원가·토지매입비·공사비·금융비는 선택한 사업비 시점의 값이며, 개발기간·연면적은 현재 프로젝트 개요의 자료를 사용합니다. 연결할 원본 값이 없는 지표는 빈값으로 표시하고 명시적 0은 보존합니다.
- 조달 구조는 기존 대출 약정액과 출자액에 연결합니다. 명시적 트랜치가 없는 대출은 유형·순위로 묶습니다. 막대의 호버·키보드 포커스·클릭으로 해당 대주·출자자 열을 제자리에서 강조합니다. 기관명은 조회 텍스트입니다.
- 기존 대출·출자 입력, 잔액, 가중평균 ALL-IN, 조달 내역, 원가관리 데이터 및 운영 연결은 보존합니다. 수동 단계와 예시 자료는 상세 표에서만 조회하며 상단 현재값에는 영향을 주지 않습니다.
