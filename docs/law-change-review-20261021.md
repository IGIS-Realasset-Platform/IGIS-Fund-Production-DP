# 법령 변경대비·검토후보 보완 명세

## 범위와 현재 원인

승인 범위는 법령 수집/비교 서비스, 법령 모니터 화면과 법령 전용 검사입니다. 공통 인증·알림·사업원장·원금액·확정본·계약·권한·기존 검토기록은 변경하지 않습니다. 실제 DB 쓰기·키 열람·원격 배포는 하지 않습니다.

현행 collector는 공식 상세 응답의 조문을 판본에 연결하지 않고 지문만 보관합니다. 변경 목록은 일반 제목을 반복하며, 조건 없는 공식 변경에 기존 샘플 분류를 사용하면 모든 프로젝트가 통과합니다.

현재 정제 확인자료는194관리항목/184변경, 공식 이관158/API26, 개정문157개, record-level articles/comparison0입니다. 이것은184개가 오늘 새로 개정됐거나 모두 첫 기준이라는 뜻이 아닙니다. 이전 ID·발견시각·원문·검토 연결은 유지합니다.

## 데이터와 소비자

- 국가법령정보센터 `oldAndNew`/`admrulOldAndNew`의 신구기본정보·공식 비교행을 우선합니다. 두 시행판본을 직접 비교할 때는 같은 공식 법령ID·종류, 정확 MST/시행일을 확인합니다.
- 조문 본문은194개 전체 참조응답에 일괄 복제하지 않습니다. 현laws payload가 약4.33MB이므로 상세에서 닫힌 `comparison=1` 조회를 사용합니다.
- 상태는 `verified`, `unchanged`, `baseline_only`, `before_unavailable`, `after_unavailable`, `attachment_only`, `identity_mismatch`, `unsupported` 등으로 구별합니다. 신구법 미제공과 네트워크 실패도 구별합니다.
- 신구 비교는 `basis`, `before`, `after`, `changes`, `counts`, `summary`, `limitations`를 반환합니다. 모든 문구는 공식 응답의 원문 또는 그 위치/건수에 한정하며 법률 효과를 생성하지 않습니다.
- 기존 변경목록의 원본과 ID/alias/검토 메모는 보존합니다. 화면용 요약·비교·후보는 읽기 projection 또는 비동기 캐시에 둡니다.
- 실제 소비자는 collector → 법령 snapshot → canonical event projection → 법령 목록 → 상세 비교 → 검토후보 → 명시 검토저장입니다. 공식 source URL과 선택 판본의 식별값은 각 단계에서 유지합니다.
- 일반회원/프로젝트 격리는 기존 인증·조회 권한을 그대로 사용하며, 임의 URL/키/쿼리는 받지 않습니다. 공통 라우트 연결은 root 소유입니다.

## 구현 계약과 검수 상태

- 새 `server/law-comparison.mjs`는 `oldAndNew`와 실제 확인한 `AdmRulOldAndNewService`를 해석합니다. 공식 비교행 번호의 일대일 대응, 양쪽 법령ID·종류·정확 시행일·요청 판본·시간 순서를 확인합니다. 항·호로 분리된 비교행도 직전 조문 제목을 유지합니다. 같은 이름만으로 법률·시행령을 합치지 않습니다.
- 상세 비교의 외부 조회는 최대6요청/30초/누적32MiB이며 각 응답의 기존 제한도 유지합니다. 비교 텍스트는8MiB, 행5000개 이내입니다. `comparison=1`, 선택 판본과 선택적 `beforeSequence`/`beforeEffectiveAt`만 소비하며 임의 URL은 받지 않습니다. 공식 신구법이 정확한 판본 쌍을 제공하지 않으면 명시된 이전 공식 판본의 본문과 비교합니다. 같은MST·같은 시행일의 과거 본문을 확보하지 못한 지문변경은 이전 공포본으로 대체하지 않습니다.
- 새 수집의 `observationKind`는 `first_catalog_observation`/`new_version_observation`/`same_version_body_change`를 구분합니다. 기존184개 변경의 과거 ID·발견시각·원문·검토기록은 소급 재분류하지 않습니다. 기존 개정문이 있는157건은 표시할 수 있는 근거가 이미 있다는 뜻이며, 모든 조문의 완전한 전후 비교를 확보했다는 뜻은 아닙니다.
- 현재·예정 판본의 개정문은 수집 시 최대1400자 발췌와 `amendmentExcerpted`만 연결합니다. 상세 응답에는 확보한 `amendmentText`/`amendmentReason`을 둡니다.194개 전체 본문을 snapshot으로 복제하지 않습니다.
- `comparison`은 `basis`·양쪽 판본·`changes`·`counts`·`contentComplete`·`limitations`를 제공합니다. 정확 두 판본의 조문 외에 부칙·별표 본문 차이도 검사하지만 첨부파일 내부 문구를 비교했다고 주장하지 않습니다. 공식 생략/미제공은 신설·삭제·변경 없음으로 추측하지 않습니다.
- 공식 신구법 공개 예시의 확인범위: 국가법령은 신설2/문구변경201/동일1/비교본문 미확보25행입니다. 이는 해당2012년 공개 예시의 비교행 집계이며 현재194개 관리법령의 실시간 변경건수가 아닙니다. 행정규칙 공개 예시도 정확 양쪽 판본과 실제 문구 차이를 검사했습니다. 실제 신규 운영 상세 호출·194개 전수 신구법 확보는 아직 수행하지 않았습니다.
- 프로젝트 분류는 `candidate`(명시확인목록 ID·정확 인허가 근거·입력지역 조례 후보), `insufficient`(판본/관할/연결 결측 또는 법률·시행령 종류 차이), `not_linked`(현재 연결 근거 없음) 중 하나입니다. 모두 `appliesToProject:false`이며 법적 영향 확정이 아닙니다. 부족한 사업조건은 별도 명시합니다. 모든 접근 가능한 실제 프로젝트를 상세에서 한 번씩 표시하여 “후보에 없음=법적으로 무관”으로 숨기지 않습니다. 동명 광주·광역/기초와 다른 지역 반례를 포함합니다.
- 프로젝트별 확인목록은 현재 접근 가능한·존재하는 사업에 대한 서버 읽기 결과를 사용합니다. 후보 계산/상세 열기/비교/취소는 검토기록·감사를 생성하지 않습니다. 사용자의 명시적 저장만 기존 workspace 저장 경로를 사용하고 신규1개 또는 기존ID의 검토를 기록합니다. 저장 직전 프로젝트 존재·현재 문맥·수정 권한·공식 source version/변경ID/판본 메타·후보 근거·중복기록을 다시 검사합니다. 기존 사용자 검토·이력은 자동 초기화하지 않습니다.
- 새 reference를 읽으면 과거 비교 캐시를 비우고, 닫힌 창·사업 전환·새 요청 뒤 도착한 응답은 다른 화면을 다시 열지 않습니다. 복수 시행일은 각각 선택해 비교합니다.

### 증거 및 남은 범위

1. 현재 제품 의미실패4개(가지조문 식별 손실/비교 인자 미소비/제목 반복/전사업 후보 오탐)를 수정 전 직접 재현했습니다: `.build/followup-20261021/law-initial-product-red.json`. 모듈 부재·브라우저 실행환경·검사 자료 준비 실패는 제품 RED로 세지 않았습니다.
2. 집중/법령 회귀20종은 `.build/followup-20261021/run-law-focused.mjs`로 실행했습니다. 최종 `.build/followup-20261021/law-focused-1792562480732.json`은20/20종 통과·소스지문 불변입니다. 신규 의미검사4+비교17+후보9+워크플로15=45개와 공통라우트14개를 포함합니다. 같은MST·시행일 중복 메타의 동일 번호표기(제827호/00827)는 허용하지만 진짜 공포번호·공포일 충돌을 마지막 값으로 덮어쓰지 않는 반례도 RED 후 교정했습니다. 구 자동 impact 생성 기대3개는 승인된 조회0쓰기·수기검토보존 기준으로 명시 대체했으며 서버403·금액·공식 원문·ID·alias 보존 검사는 유지합니다. 새 projectWatches SELECT를 모르는 구 stub1건과 VM의 누락 브라우저 전역은 검사 준비 오류로 별도 확인했습니다.
3. 격리 Edge 실제 화면: `tests/followup121-law-browser.mjs`, `.build/followup-20261021/law-browser-2026-10-21T06-01-26-294Z/evidence.json`. 최신 법령 모듈·CSS·비교모듈 지문과 실제 저장한 공식 공개 비교 응답을 사용하여1440/390px, 전후 실제 문구·생략25·2열/1열·가로넘침0·Escape·오류/재시도·명시검토1/자동0을 검사했습니다. 배포된 최종 전체 HTML·실제 로그인·실제 DB·194개 자료 전체의 end-to-end 검사로 확대하지 않습니다.
4. 실제 운영 API 승인/응답, 운영 상세 판본별 확보와 지역별 법적 적용·예외·경과조치는 별도 남은 검토입니다. 키 열람·실제 DB 쓰기·원격 배포는 이 작업에서0입니다.
