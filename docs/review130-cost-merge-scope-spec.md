# REVIEW130 — 연결 계약·VAT가 있는 비용 합치기

추가 실제 브라우저 검수의 정상 합치기2흐름에서 금액 보호검사가 작업을 차단했습니다. 운영 DB에는 쓰지 않았습니다. 확인된 같은 원인과 연결 소비자를 교정하며 금액검사를 없애거나 원금액을 보정하지 않습니다.

## 독립 반례

가상 원가1,000,001원(별도 범위 없음)과2,000,000원(다른 명시 범위), 외부 독립 원가100,000,000원입니다. 합친 관리행은3,000,001원, 전체는103,000,001원이어야 합니다. 실제로는 첫 원자료가 새 상위의 범위를 상속해 같은 예산의 중복으로 오인됐습니다.

또한 삭제 별명이 된 원래 ID의 VAT 조회가 현재 상위행 금액을 읽거나 null이 되면 같은 원자료의 실제 변경이 없는데 변경 경고가 생깁니다. 양쪽 원래 비용에 연결된 VAT·계약·과거 확정본을 따로 대조해야 합니다.

## 필요한 최소 교정

| 경계 | 통과 기준 |
|---|---|
| 범위 | 이동 직전의 실제 범위 또는 범위 부재를 내부 메타로 보존. 새 업무 범위 ID나 사용자 입력/설명 패널을 만들지 않음 |
| 합계 | 같은 예산의 진짜 중복은 차단하고 두 독립 예산은 정상 합산. 미입력/0·계산 상위/별도 입력·분해 가족을 구분 |
| VAT | 원래 from/to 각각의 현재 원자료 ID 집합 금액을 읽음. 합친 전체금액으로 재귀속하거나 옛 금액 상수로 고정하지 않음. 한쪽 후속 수정은 그쪽의 실제 변경으로 추적 |
| 계약·확정본 | 계약/VAT 원문·sourceId·원금액과 기존 확정본 바이트를 보존. 현재 해석의 보완으로 옛 원본을 덮지 않음 |
| 호출 계약 | 새 복사행의 비용유형 연결 method/reason은 실제 새 동작을 표시하고 원본 binding은 불변. raw 인자가 context를 덮는 API 계약을 실제 반환값으로 확인 |
| 서버 | 기존 v3 등 정상 원자료 복사만 원본 ID·코드/유형·금액/미입력·명칭·실제 합치기 관계를 대조해 허용. 신규 legacy 유형·임의금액·원본 없는 복사·거짓 관계·중복 복사를 허용하지 않음 |
| 관련 이동 | 명시 분해의 같은 가족 합산은 유지. 범위를 손상하는 드래그 이동은 저장 전 차단. 확인된 원인 없이 모든 이동 의미를 바꾸지 않음 |

현재 명시적 하위분해(`costBreakdown`)를 이미 구성한 항목/그 하위의 합치기는 원래 전환 계보와 서버 불변조건을 손상하므로 선택과 실제 호출에서 사전 차단합니다. 일반 원자료 합치기·기존 단순 하위 이동과 구별하며, 지원하지 않는 새 중첩 분해구조를 추측해서 만들지 않습니다. 이는 기존 실제 서버에서422로 거절되던 무효 경로의 교정이며 정상 동작하던 분해 입력을 삭제하는 변경이 아닙니다.

정상 저장·dirty 취소의 제공된 선택지·열린 중 대상 삭제·부모/초점·실패 무쓰기는 PC와390폭으로 분리합니다. 브라우저의 모형 HTTP200은 실제 서버의 허용을 증명하지 않으므로 실제 중앙 저장 검증함수도 별도로 실행합니다. 제품·시험 준비 오류·정책상 차단은 서로 다른 결과로 남깁니다.

되돌리기는 새 합치기 메타를 모르는 옛 화면으로 코드만 교체해도 안전하다고 가정하지 않습니다. 새 메타 사용 여부와 해당 읽기/합산 소비자의 호환성을 확인하고, 호환성이 없는 옛 코드를 쓰기 위해 사용자 기록·금액·과거 확정본을 지우지 않습니다.
