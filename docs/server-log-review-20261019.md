다음 작업에서는 먼저 기존 승인 프로필로 이 앱의 `project inspect`를 시도하고 프로젝트 ID·소유자를 대조합니다. 성공하면 같은 프로필의 `logs runtime`과 `logs requests`에서 이 앱·정확한 배포·시간 구간을 고정합니다. 프로젝트 조회 성공만으로 로그 성공을 가정하지 않습니다. 인증이 실제 만료/회수된 경우에만 공식 기기 인증을 다시 요청하며 매번 재연결·재부팅·새 프로젝트 생성부터 시작하지 않습니다. `.build`는 Git에서 제외되므로 다른 PC로 인증정보가 이전되는 것은 아닙니다.

설치는 공식 npm의 `vercel@64.5.0`·무결성 `sha512-JsWnLGHojqd0YKmLeU4NHpeCEX7/jIKNydBMNf0DGJe5W/jVb+j8lMekLkCIXqFTb8LObLoAe+OZ6/XJt4AhyQ==`를 고정했고 설치 스크립트는 실행하지 않았습니다. 실행파일과 새 인증은 프로젝트 내부에 두었으나, pnpm11이 지정 설정과 달리 Windows 공용 패키지 캐시도 사용했습니다. 따라서 모든 파일 쓰기가 프로젝트 안에만 있었다고 주장하지 않으며 공유 캐시는 삭제하지 않았습니다. 추가 설치가 필요하면 실제 지원되는 명령줄 `--store-dir` 옵션으로 범위를 재확인합니다.
