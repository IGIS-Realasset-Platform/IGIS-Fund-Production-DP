# CENTER120-17 업체 공식자료 자동수집 계약

## 후보22 후속 교정과 실제 부분실패 경계

후보18의238/245 성공 뒤 후보20에서는 검색어 교정의 재순회 중166출처/158성공·partial1·KACEM TLS1·설정필요6으로 끝났습니다. 첫 업체의 공식 상세에 `Issuer Rating`이 있지만 닫힌 파서가 지원하지 않아 등급0이 됐고 첫 실패가 뒤 회사 조회도 막았습니다. 원사이트의 빈자료나 인증값 부재로 잘못 설명하지 않습니다.

후보22는 원문 상품명과 별도 `issuer_credit` 유형을 보존하고 미확정 법인·대표등급은 그대로 둡니다. 실패한 회사는 닫힌 `creditPendingCompanyKeys`에 남기되 다음 회사로 진행하고 순회 끝에서는 정상회사도 다음 갱신 기회를 갖습니다. 신규28·관련11군과 공식 단건 등급0→1은 확인했지만 새 배포의 cron/DB 검수는 별도입니다. 최대200요청/70초/32MiB·623결과·판본 CAS와 원문/댓글/원장 보호를 약화하지 않습니다. 근거는 공식 KIS 평가방법론과 `tests/center120-credit-product-retry.mjs`입니다.

아래 초기 단계의 특정 해시·원격 미실행 표기는 당시 이력입니다. 최신 수집·보존 증거는 CENTER120 수정대장과 별도 최종 검증 기록을 우선하며, 자연예약·미설정키·원기관 TLS·법인/면적 근거는 완료로 확대하지 않습니다.

2026-10-20 현재 사용자 승인 범위는 기존 포털의 자동수집 코드를 복사하는 것이 아니라, 같은 기능을 이 앱에 새로 구현하는 것입니다. 원사이트의 계정·DB·배포·비밀설정은 변경하지 않습니다. 이 문서는 구현·시험 중인 계약이며 정식 자동운영 완료 기록이 아닙니다.

## 저장 경계

- 수집기는 외부 공개 원문을 읽고 새 스냅샷 후보를 반환하는 순수 함수입니다. DB·프로젝트 원장·댓글을 직접 변경하지 않습니다.
- `collectPartnerSnapshot({previous, configuration, fetcher, clock, budgetMs, continuation, rankingsCollector})`는 `status`, `sourceResults`, `requestedCount`, `checkedCount`, `payload`, `continuation`을 반환합니다.
- `payload.groups/companies/market`는 기존 조회 계약을 유지합니다. `automation.sources`에 자료원별 마지막 시도·마지막 성공·오류코드·자료기간·범위·지문을 기록합니다.
- 실패·인증설정 없음·부분 응답을 정상 0건으로 바꾸지 않습니다. 이전 정상 그룹·업체 자료·단위·기간은 보존합니다. 원문이 달라진 경우 기존 지문과 새 지문을 정정 기록에 남깁니다. 전체 과거 스냅샷의 불변 보관·중복 lease는 예약 실행 연결 담당에서 처리합니다.
- 출처 고유 등록번호가 검증된 경우만 기존 업체키와 연결합니다. 이름·순위·표시행 번호는 업체 동일성을 보장하지 않습니다. 확인되지 않은 CM/KACEM 행은 새 출처행으로 구별하며 댓글키를 이름으로 이전하지 않습니다.

## 외부 요청 및 재시도

- 공통 기본90초/80요청, 승인된 운영은 최대70초/200요청·개별15초·텍스트2MiB·파일12MiB·누적32MiB로 제한합니다. 현재150개 공개 회사의 뉴스 최대150요청과 기관/공시/원표 약15요청을 수용하는 유한 상한이며 무제한 재시도가 아닙니다. 기관 조회는 동시3개, 회사별 뉴스는 순차 처리합니다. 예약 실행 전체300초와 법령 수집 예산은 별도입니다. KICT만 일반 공개 익명 세션의 정확한 읽기 POST `/archive/list`, `/notice/list`, `/archive/get`을 허용하며 다른 POST는 거부합니다. 상세 ID는 방금 읽은 공식 목록과 대조합니다. 익명 CSRF·쿠키는 요청 중 메모리에만 두고 저장·출력하거나 다른 호스트에 전달하지 않습니다.
- 공식 허용 호스트·HTTPS·확인한 읽기 경로만 요청합니다. 다른 호스트 redirect, 사용자정보 포함 URL, 임의 내부주소·포트, 무한 retry는 거부합니다.
- 인증값은 함수 인수로만 받고 결과·오류·출처 URL에 넣지 않습니다. fetcher 오류 원문은 로그/결과에 전달하지 않습니다.
- 회사 뉴스는 정확한 현재 업체키 전체를 시간·크기·요청 예산 안에서 시도합니다. 동일 검색URL의 응답만 이번 실행 메모리에서 재사용하고 회사키·댓글·기사주체를 합치지 않습니다. 429는 해당 호스트를 이번 실행에서 즉시 중단하며 재시도하지 않습니다. 시간이 부족하거나 중단되면 다음 커서와 미확인 수를 반환합니다. 누락 기업을 삭제하지 않으며 무키 RSS 보관창을 넘긴 누락을 완전 복구로 표시하지 않습니다.
- source fingerprint는 정규화한 실제 내용 기준입니다. 조회시각만 달라졌을 때 불필요한 정정 이력을 만들지 않습니다.

## 검사 기준

새 구현은 계약 부재를 제품 결함 재현으로 주장하지 않고 새 기능 RED로 기록합니다. 실제 내용과 독립 fixture를 사용해 정상/빈 RSS/잘못된 XML/HTML/중복 식별자/다른 업체/정정/과거값 보존/이전값 불변/기간·단위 충돌/비밀 비노출/크기·시간·호스트 상한을 검사합니다. 실제 공식 호출·단위시험·예약 자연실행·정식 게시 상태는 각각 기록합니다.

현재 자료원 키가 없거나 전체원문 판독이 끝나지 않은 기능을 완료 처리하지 않습니다. 자료 복구, 새 수집기 구현, 실제 원격 수집, 예약 자연 실행은 서로 다른 완료 기준입니다.

## 2026-10-20 실제 공개원문 검증

새 수집기로 DART 최근50공시·Google92검색기사·KICT 공식 통계표를 실제 읽었습니다. 원표는 59,232바이트이며 SHA-256 `763dc705bb8aef5e89c7b9582691da3478554493c8b863c5122d1f46cd68ea90`입니다. `건설공사비지수(2020=100)` 1개 시트의 24개 데이터행×320개월(2000-01~2026-08), 총7,680개 숫자를 원표와 대조했습니다. 동일 계층의 명시 반복4행은 모든320값이 같은지 확인한 뒤 원문 행번호 별칭으로 보존해20계열로 읽습니다. 마지막 달은 원문대로 잠정값이며, 전년대비는 실제 전년 동월과 비교합니다. 원본은 재계산·수정하지 않았습니다.

이는 기존18계열을 덮거나38계열을 기본화면에 모두 노출하는 결정이 아닙니다. 새 출처판본의20계열을 추가 보존하고, 회사 기본화면 수준을 유지하기 위한 표시 역할은 건설총계1 `primary`, 기존 세부4 `detail`, 나머지15 `archive`입니다. 제품 화면에서 어떤 출처판본을 선택할지는 별도 연결 검수 대상입니다. 기관 자체코드를 공식 통계표 ID로 가장하지 않고 `officialSeriesId:null`, 원표 계층경로 `sourceSeriesKey`, 원문 행번호 `sourceRows`로 근거를 남깁니다. 자료 기준월과 원사이트 등록·예약게시·수정시각은 `publication`으로 구별합니다.

실행 근거는 비공개 중간검사 폴더의 `partner-collector-public-verification.json`, `partner-kict-original-verification.json`이며 최종 배포/DB 쓰기·자연 예약 실행의 증거가 아닙니다. 독립 단위검사는 RSS 긴 식별자·발행사·형식오류·상한·부분실패·원문바이트 해시·계열단위·기존값 보존을 포함합니다.

초기 수집기 단계의18개 단위검사와 당시6개 검사군93개는 해당 소스 지문 고정 상태에서 통과했습니다. 순위 수집기와 실제 문서 Worker를 함께 사용한 초기 `partner-collector-integrated-verification.json`은 공식16요청으로 CAK/CM/ETIS2종 각30행·KICT20계열·DART50공시·Google92기사를 확인하고, 실패한 KACEM 기존표/업체/코멘트·원래 시계열을 보존했습니다. 독립 검토에서 `stream.cancel()`이 끝나지 않으면 용량 오류 후에도 대기하는 반례가 나왔고, 실패검사로 재현한 뒤 전송 중단과 비대기 취소를 적용해 상한을 보완했습니다. 이 과거 검사는 아래 최종 전체150 실측·운영 연결 검수와 구분하며 실제 서버 예약 실행이나 모든 업체의 신용/계약 검증 완료를 뜻하지 않습니다.
