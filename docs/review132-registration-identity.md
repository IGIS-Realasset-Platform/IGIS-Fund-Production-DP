# REVIEW132 법인 식별과 연간 집계 경계

2026-10-30. 독립 QA 후보를 최초 초기화·현재 연간집계 소비자·충돌 재조회 경계와 대조했습니다. 법적 등록대상 기준이나 사용자 화면을 새로 만들지 않았습니다.

## 결함의 정확 범위

`annualRegistrationSummary`는 단순히 `x.entityId===p.entityId`로 비교해 undefined/null/빈값 두 개 또는 없어진 같은 ID를 실제 같은 법인으로 취급했습니다. 삭제된 사업은 미입력연도 목록에 남고, 삭제된 외부확인행은 확정0원처럼 읽힐 수 있었습니다.

일반 최초 부트의 `legal.initialize`는 누락ID를 각 사업별로 보완하므로 초기화 이전의 함수검사만으로 일반 최초 화면의 잘못된 합계 노출을 주장하지 않습니다. 현재 등록 본문의 `A.legal.ui.annual`은 빈 화면을 반환하며 과거 연간표는 계속 숨겨집니다.

실제 소비자 연결은 정상 로그인 부트 → 합성 workspace PUT409 → 기존 `storage-conflict-reload` 동작 → 현재 연간집계 헬퍼로 재현했습니다. 재조회는 원본에 없는 법인ID를 임의 생성하지 않으므로 수정 전 다른 사업 P1/P2가 집계목록에 함께 들어왔습니다. 합계 자체는 외부확인 부재로 미확정이었고, 현재 일반 화면의 확정 합계가 잘못 표시됐다고 확대하지 않습니다.

## 최소 교정과 보존

유효한 원천 식별값과 살아있는 유일 법인기록이 있을 때만 같은 법인·같은 연도의 미삭제 사업을 집계합니다. 원천이 없으면 기존 미확인 계약대로 `known:false`, `projects:[]`이며 연간 합계는 미확정입니다. 삭제된 외부확인행을 명시적인0 확인으로 바꾸지 않습니다. 이름으로 다른 법인을 연결하거나 원자료를 수정하지 않습니다.

정상 공유법인의1000+2500=3500㎡, 독립 법인의1000㎡, 다른연도 제외, 명시 외부0과 미입력, 기존 수기777/888/999 값, 건축/토지 분류와 면적 원본을 보존합니다. 최초 초기화의 별도ID 보완과 정상 등록 UI는 유지합니다.

`tests/review132-registration-identity.mjs`의 유효 RED는2통과/7실패였고 교정 후9개 모두 통과했습니다. 독립 QA의 `review132-qa-entity-scope`도5개 통과했습니다. 초기 시험에서 undefined 인자에 함수 기본값이 주입되던 준비 실수는 바로잡아 실제 누락ID를 주입한 RED와 구분했습니다. 정확 실행은 `.build/review132-backend/registration-identity-valid-red.json`, `registration-identity-green.json`에 있습니다. 실제 운영DB쓰기·원본조직 변경·새 법적판정은0건입니다.
