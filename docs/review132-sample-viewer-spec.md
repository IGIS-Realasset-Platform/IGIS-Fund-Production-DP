# SAMPLE132 — 추가 샘플 조회 전용 접속

사용자가 승인한 추가6명은 orgdb에서 확인한 이메일을 별도 서버설정 `DP_SAMPLE_VIEWER_EMAILS`에 둡니다. 실제 이메일은 소스·검사·공개문서에 게시하지 않습니다. 기존 `DP_ALLOWED_EMAILS`는 변경하지 않습니다.

원천readonly확인은정확6행/6메일/공란0·기존app_user/admin/member0입니다. 민감한기존허용명단은복호화/재발급하지않고,배포서버의정상 `readAuthConfiguration` 경로에서 regular/sample/union/overlap **숫자만**확인합니다. 실제교집합을보지않고0으로선언하지않습니다.

검사는합성메일과독립적인엄격샘플기대값으로runtime/auth/grant/직접API/개인상태·기존regular동작을검사합니다. 새계정/암호·실제메일/초대/OTP·운영설정/DB쓰기·배포는구현담당자가수행하지않습니다. 실제활성화/실회원접속은root의별도검수이며단순파일생성·합성통과를대신쓰지않습니다.

서버는 확인된 세션 이메일과 서버 설정에서만 sample-only를 판정합니다. `GET /api/workspace`는 해당 사용자에게만 `permissions: {sampleOnly: true}`를 추가합니다. 일반 사용자의 응답에는 이 키를 새로 넣지 않습니다. 클라이언트는 이 값을 표시 제한에 사용하고 서버의 권한 판단을 대신하지 않습니다. 로그아웃과 일반 사용자 재로그인에서는 해당 표시 상태를 초기화합니다.

개인 알림의 읽음·삭제·복원은 본인의 상태에만 기록하며 현재 엄격 샘플 3개에서 나온 원천 식별자만 허용합니다. 사업ID와 이동대상의 사업ID가 다른 알림은 제외합니다. 다른 실제 사업과 공유한 법인의 본문, 공용 내부댓글, 전역 원천·시장·직원 목록은 제공하지 않습니다. 샘플 프로젝트에 연결된 회사는 식별자·이름만 제공합니다.

서버 구현 집중검사는 `tests/review132-sample-viewer-policy.mjs`의 15개와 `tests/review132-sample-viewer-auth.mjs`의 5개를 통과했습니다. 실제 고정 Better Auth 라이브러리를 메모리 저장소와 발송하지 않는 대체함수로 실행해 미인증·인증·로그아웃·재로그인·겹친 명단·초기관리자 일치까지 확인했습니다. 기존 인증·접근·알림·댓글·아카이브·직원·저장 경계의 영향 회귀 29개 실행파일도 통과했으며 실행 중 제품 소스 변경은 없습니다. 준비 실패·운영 실회원 검수를 통과로 포함하지 않습니다.

구 C95는 새 설정을 무시하고 원래 허용명단만 사용함을 당시 공개 소스의 `readAuthConfiguration` 원함수로 대조했습니다. 대조물은 `tests/support/review132-c95-auth-baseline.json`이며 source commit `9427ff59160cc7223a376b9d88f67cc106eb0642`, 원함수 SHA256 `d7b5d1da693a64e77b9eab1b2a88fa283d7693de89134795861844c6fa971b08`입니다. 환경변수 이름과 검사 코드만 포함하며 실제 환경값·개인 이메일·자격값은 포함하지 않습니다. 대조물은 독립 실행검사 수에 추가하지 않습니다.

설정 활성화 순서는 기존 `DP_ALLOWED_EMAILS`를 보존한 채 새 명단 하나를 설정한 뒤 검증된 새 코드를 게시하는 것입니다. 구 C95에서 새 사용자의 editor 권한이 열리는 중간 단계는 없습니다. 실제 배포의 regular/sample/union/overlap 수치는 정상 서버 설정 경로에서 숫자만 대조하고 운영 영수증에 따로 기록합니다. 기존 계정 0건이므로 계정·암호를 선발급하거나 기존 회원의 권한을 일괄 수정할 필요가 없으며, 정상 이메일 인증이 끝날 때 세 샘플의 viewer를 부여합니다.
