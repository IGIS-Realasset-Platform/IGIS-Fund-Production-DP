## 변경·보존 경계

1. 재접속은권한검사된GETworkspace응답한번으로부트합니다. GETsession API는기존클라이언트/다른사용처호환을위해유지합니다. 비밀번호로그인/가입POST뒤workspace의새세션·권한재검사는유지합니다.
2. workspace의정확한403 EMAIL_NOT_ALLOWED만안전한enum으로보존하고,처음미인증/만료401은일반로그인,그403은기억email제거로그인,503/네트워크는자료를열지않는재시도로구분합니다. 임의오류본문/민감값반사와권한실패숨김은금지합니다.
3. 인증/자료준비중은중립적인불러오는중표시이며,401확정전로그인폼을보이지않고권한확정전업무화면/기존자료를보이지않습니다. 문구만바꿔속도가개선됐다고보고하지않습니다.
4. 확인된 초기화 CPU 병목에만 최소 수정합니다. 원금액·코드·확정본·계약/VAT·이력·삭제·편집 결과·프로젝트 격리는 불변입니다. 동기적인 조회·렌더 호출 한 번 안에서만 읽기 전용 계산을 재사용하고, 정상 종료와 예외 모두 finally에서 즉시 폐기합니다. 다음 편집·다음 렌더·다른 프로젝트로 넘어가는 지속 캐시, 업무자료의 브라우저 저장, 권한·인증 캐시는 추가하지 않습니다. 초기화 중 변경과 호출자 배열 변경, 중첩 호출, 같은 ID/빈 ID를 가진 다른 객체를 반례로 검사합니다.
5. 폰트중복은cloud HTML에서한번내장한head원문을인쇄자산에서도공유하는방식으로줄입니다. 실제DOM에서폰트원문/해시와한글표시가같은지검증하며비cloud과거HTML은변경하지않습니다.

## 작업 도구 오류와 제품 지연의 구분

- `Automatic approval review failed: Selected model is at capacity`는 명령 실행 전 별도 승인 검토에서 발생했습니다. 일부 같은 경로의 읽기는 성공했고 다른 호출은 용량 오류 또는 검토 제한시간 초과였습니다. 실행되지 않은 호출은 제품 오류나 새 검사 통과로 세지 않습니다.
- 사용량 조회는 일반 사용 허용·한도 미도달을 반환했습니다. 플랫폼 계정·Supabase·Vercel 재연결이나 DB 변경을 해결책으로 적용하지 않았습니다.
- [공식 권한 안내](https://learn.chatgpt.com/docs/permission-modes)에 따라 사용자가 현재 채팅을 `Ask for approval`로 변경했다고 확인했습니다. 보안 격리·작업공간 경계는 유지하며, 전체 접근·승인 생략·전역 설정 직접 수정은 하지 않았습니다. 이후 읽기 성공은 관측했지만 이것만으로 용량 문제가 영구 해결됐다고 단정하지 않습니다.
- 정상 경로로 실제 수정·자동검사·브라우저 실행·최종 배포가 각각 끝나야 PERF115 완료로 판정합니다. 원본 DB에는 쓰기 검사를 하지 않습니다.
