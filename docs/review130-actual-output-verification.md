# REVIEW130 · 실제 C86 출력 원문 검수

2026-10-29 마감 기록입니다. C86 당시의 실제 운영 UI와 DB 저장본에서 읽은 승인된 가상 C 사업 인쇄 원문을 격리 PDF 엔진에 그대로 넣었습니다. App.state나 모형 값으로 보고서를 다시 만들지 않았고 원장 금액을 추정하지 않았습니다. 실제 기관 제출을 의미하지 않습니다. 후속 법령 자동수집 서버 교정과 제품 소스 지문 재확정은 별도입니다.

| 유형 | 쪽수 | 원문·출력 확인 |
|---|---:|---|
| 사업계획 등 |8|실제 UI 미리보기 원문, 선택 유형 표시 확인|
| 추진현황 |8|실제 DB 보관본문 원문과 byte동일, 세 추진경과 문장 각각1회|
| 취소·중단 |1|해당 양식 출력만 확인, 취소·중단 사건 신규생성 없음|
| 완료 |1|해당 양식 출력만 확인, 준공·완료 사건 신규생성 없음|

총4PDF·18쪽에서 원문 대비 정규화 문자 누락0·대체문자0, A4와 셀/페이지 밖 침범0을 확인했습니다. 인쇄 원문에 수정 입력·버튼은 없으며 포함된 원래 글꼴을 사용했습니다. 고유 PNG11개를 직접 확인하고 나머지7쪽은 사업계획/추진현황의 같은 페이지끼리 PNG전체 byte동일로 연결했습니다. 자세한 지문은 [동일 JSON](review130-actual-output-verification.json)에 있습니다.

사업계획·추진현황의8쪽에는 신고문·날짜·서명·첨부목록과 작성방법이 함께 있어 전체 원문8쪽을 보존했습니다. 운영 UI의7쪽 선택/미리보기 상태와 같은 결과라고 표현하지 않습니다. 좁은 공식 금융/날짜 칸의 줄바꿈은 있으나 문자 소실·침범과 구별합니다. 원래 내용의 업무상 완전성·법정 비용분류 적정성을 이번 문자/레이아웃 검사로 새로 확정하지 않습니다.

운영 화면의 인쇄버튼은 native print dialog에서 CDP 도구 timeout이 발생하여 인쇄 완료로 수락하지 않았습니다. reload로 복구됐다는 사실도 인쇄 성공으로 세지 않습니다. 이는 사용자 승인 대기가 아니라 도구 한계에 따른 미검증입니다. 실제 UI/API/DB 저장과 원금액·계약·VAT·확정본 비교는 [실제 DB 기록](review130-c86-live-db-verification.json), 요청/오류 범위는 [서버 로그 기록](review130-c86-server-logs.json)과 분리합니다. 기존 legacy메타3건의 독립 before 비교는 별도 미검증이고 원래 보관본문은0건이었음을 유지합니다.

원문 HTML·PDF·이미지·업무값은 비공개 .build 검수자료에만 보관하며 이 공개 문서나 public GitHub에 첨부하지 않습니다. 렌더러의 실제 DB 쓰기·외부 요청·제품/원문 변경은0회입니다. 이 검수로 QA130-06의 전수요구 완료를 선언하지 않습니다.
