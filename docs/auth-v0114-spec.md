# v0.11.4 선택형 로그인 상태 유지

기준일: 2026-10-19. 사용자는 정식주소에서 가입·비밀번호 재로그인 완료를 확인했고, 로그인정보 기억 또는 자동로그인을 추가 요청했습니다. 서버 지정12메일만 가입·로그인하는 정책은 그대로입니다.

## 승인 흐름과 보존

- 로그인 폼에 기본 해제된 `로그인 상태 유지(7일)` 체크박스 하나만 추가합니다. 선택은 비밀번호 로그인에만 적용하고 최초가입/메일확인 흐름은 변경하지 않습니다.
- 선택하면 이 브라우저의 HTTPOnly/Secure/SameSite Strict/host-only 세션을 최대7일 유지합니다. 비선택·이전 클라이언트는 기존8시간 정책을 보존합니다. 현재 로그인한 세션을 몰래 연장하지 않고 다음 비밀번호 로그인부터 선택합니다.
- 서버의 `rememberMe`는 생략 또는 boolean만 허용합니다. 문자열/숫자로 기간을 늘리지 못하며 최대기간은 서버에서 고정합니다. 세션 재조회가 무제한 수명연장이 되지 않도록 절대 만료를 검사합니다.
- 비밀번호·세션토큰·업무자료를 localStorage/sessionStorage/상태·초안·로그에 저장하지 않습니다. 브라우저 비밀번호 관리자의 기존 username/current-password 자동완성은 유지하되 브라우저 설정을 임의 변경하지 않습니다.
- 선택한 로그인에서 작업공간 진입까지 성공했을 때만 이메일 하나를 전용 origin-local 키에 최대7일 기억합니다. 다음 로그인 화면에는 이메일만 채우고 체크박스는 다시 기본off입니다. 선택하지 않은 성공 로그인·명시적 로그아웃 성공·허용목록 제외403은 기억정보를 제거합니다.
- 기억정보는 버전/이메일/저장·만료시각만 포함합니다. 만료·7일초과·미래시간·비회사주소·잘못된 JSON/배열/추가필드는 복원하지 않습니다. 저장소 오류는 자동로그인과 업무 부트를 막지 않고 저장하지 않은 상태로 계속합니다. 장식 안내/배너를 추가하지 않습니다.
- 기존12메일 제한·가입8~15자·기존로그인8~128자·관리자/프로젝트권한·사용자자료·공유회사서비스 분리를 유지합니다. 로그아웃은 선택여부와 무관하게 실제 서버 세션을 회수합니다.

## 설치 라이브러리 확인에 따른 구현 경계

Better Auth1.7.8의 native rememberMe:false는 DB24시간/브라우저세션쿠키를 사용하므로 앱의기본8시간을보존하지못합니다. 앱의공개boolean과native인자는분리하고, 승인한8시간/7일두설정의발급기를선택합니다. native발급은명시한TTL의지속쿠키로유지하며 두설정에disableSessionRefresh:true를적용해조회에따른rolling연장/단축을없앱니다. 기존DB세션expiry는직접수정하지않고그대로존중합니다. 신규DB필드·DDL·서명비밀회전은없습니다.
