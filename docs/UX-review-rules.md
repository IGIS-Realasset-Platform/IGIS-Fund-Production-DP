# 프로젝트 공통 작업·UX 원칙과 재발검사

2026-10-08 초기 작성·2026-10-20 누적 보완. 인수인계 원문과 이후 대화·정정을 대조해 사용자 운영지침, 반복 오류와 현재 결정을 정리했습니다. 이미 대체된 요구는 아래 현행 결정과 분리합니다. 이 문서는 새 기능을 임의로 만드는 근거가 아니라 매 작업에서 확인할 기준입니다.

## 매번 확인하는 핵심 체크

1. 이번 요청이 답변/진단/계획/구현 중 무엇인지, 새 메시지가 추가 조건인지 대체 지시인지 확인합니다.
2. 현재 결정과 변경하지 않을 화면·자료·업무 기준을 정합니다.
3. 한 요소가 아닌 진입→선택→조작→저장/취소→복귀→출력을 점검합니다.
4. 이름·계층·단위·같은 데이터의 표시를 본표/팝업/편집/엑셀에서 대조합니다.
5. 미입력/0·현재/과거·소계/상세·예시/실제·원자료/표시모델을 구분합니다.
6. 실패 재현·집중/회귀·실제 화면·PDF/Excel 검수와 증거를 구분합니다.
7. 새 지적을 기존 원칙·재발검사에 반영하고 명세·체크리스트·최종 산출물을 동기화합니다.

### 상호작용 세부 기준

- 버튼·숫자·손잡이·열 경계는 실제 가능한 동작만 시각적으로 드러냅니다. 비활성 합계에 편집처럼 보이는 동작을 붙이지 않습니다. 사이드바는2026-10-21 최신 지시로 펼침=아이콘 없는 글자 메뉴, 접힘=메뉴 전체 숨김입니다. 접어도 이름이 보이도록 폭을 늘리는 임의안은 폐기하며, 바깥 글자 버튼으로 재열기·포커스·저장된 접힘·모바일을 검사합니다(`followup121-sidebar-text`, `followup121-sidebar-browser`).
- 분류의 본표·선택·추가 위치는 같은 고정 식별자로 연결합니다. 표시 이름을 비교해 소속을 결정하거나 이름 변경 후 임의 fallback 분류를 만들지 않습니다. 본표·팝업·부모 선택의 표시 이름은 같은 원천에서 가져옵니다.
- 접힘/검색/필터/열폭/스크롤/프로젝트 상태의 저장 범위를 구별합니다. 화면 진입·뒤로가기·다른 프로젝트 전환에서 실제 세로 스크롤 소유자를 확인해 초기화/복원합니다. 사업비 선택팝업의 새 진입은 전체 접힘·빈 검색이며 같은 팝업 세션의 조작 문맥만 유지합니다. 임시 검색 펼침이 사용자의 수동 설정을 덮지 않도록 합니다. 토글/검색으로 전체 후보와 모달을 다시 만들지 않고 실제 클릭 반응시간을 검사합니다.
- 추가 후 새 항목이 실제로 보이거나 가용 포커스로 이어지는지, 삭제 후 포커스 대상이 사라지지 않는지 확인합니다.
- 전체 UX 점검은 화면·팝업·자식 팝업의 컴포넌트 목록과 실제 실행 증거를 연결합니다. 위치/문구/정렬/크기/스크롤/키보드/최종 결과를 각각 확인하며 반복된 데이터 행의 관측수와 다른 동작의 수를 혼동하지 않습니다. 같은 DOM의 높이 왕복에서는 실제 입력칸의 초점·클릭 가능 위치·원래 스크롤을 확인하고 다른 화면의 DOM에는 이전 위치를 옮기지 않습니다. 좌표가 화면 안이라는 이유만으로 고정 헤더 뒤에 가려진 입력칸을 통과시키지 않습니다. 필수 별표·접근성 속성은 실제 기존 검증조건과 최초 표시/초안 복원/조건 전환에서 일치해야 하며 표시 교정을 새 필수정책으로 확대하지 않습니다. `aria-required="false"`와 native `required`는 서로 다른 속성이므로 단어 포함 검사로 같은 상태라고 판정하지 않습니다.
- 기존 복수 실제금액을 한 관리행으로 표시할 때 편집 경로를 없애지 않습니다. 현재셀에서 기존 입력대상을 선택하고 그 기록만 수정하는 동작, 미선택·대상삭제·참여범위 변경·저장실패를 확인합니다. 새로운 세부 비용행/조정행을 만들거나 원금액을 임의 배분하지 않습니다. 명시적 하위 분해 이후에는 계약/기성/지급의 기존 부모ID 선택·검증, 부가세의 현재 원천 null, 보고서의 보존 원자료 제외까지 실제 소비자 경계로 대조합니다. 본표의 합계가 맞거나 보고서 소스가 이전과 같다는 사실만으로 새 자료구조까지 정확하다고 판정하지 않습니다.

- 새 선택팝업의 검색/접힘과 같은 세션의 문맥을 구별합니다. 토글·검색은 기존 후보의 DOM 상태만 갱신하며 데이터 변경·저장 경계는 다시 확인합니다.
- 현재 금액 셀은 상시 수정버튼 없이 더블클릭/Enter로 편집합니다. 도급·설계·법정감리·조사는 각각 단일행이며 전문분야 하위행·편집패널을 다시 만들지 않습니다.
- 단일행 전환이 불명확 비용의 의미확정은 아닙니다. 정확한 일반유형은 현재 정의를 쓰고 기존 복합/미분류는 당시 검토코드·원문을 유지합니다. 원행/과거 JSON 외에 실제 본표/엑셀의 과거 비교금액도 전후 검사합니다.
- 회사 화면 분류와 공식 ICMS 대응·법령을 구별합니다. 실물 미술과 대체 기금, 기존자산 취득세와 신축 취득세/등기를 분리하고 당시 마스터 정의를 보존합니다.
- root/branch 연결은 분류 식별자 기준입니다. 표시명 변경 뒤 후보가 fallback 분류로 이탈하는 반례와 실제 빈검색·추가 후 상태를 검사합니다.
