# REVIEW130 요청1 · 착공·공사·준공 조회와 수정

## 원본과 범위

- 현재 정식 v0.12.9 C73와 직전 C66 HTML, 국토부 보고양식의 착공/본PF/공사·준공 항목, 승인된 33개 일괄 입력 명세를 대조합니다.
- C66은 construction19개와 공정2개를 본표에 보여줬습니다. C73은 construction11개와 공정2개만 요약하고 나머지는 폼에 남겼습니다. 착공신고일, 착공지연 사유·내용, PF지연 사유, 공사중단 사유, 공사지연 사유, 준공지연 사유·내용의 8개 조회 누락이 실제 결함입니다. 데이터 삭제와는 구별합니다.
- 현재 입력은 construction28개, 공정 기준일1개, 계약·책임준공 약정4개입니다. 별도 담당자 필드는 원장에 없으므로 추가하지 않습니다.
- 인허가 상세 4탭과 별도 상세 CSS, 법정 출력, 이력·원금액·약정·대출 만기·과거 보고서·실제 DB를 변경하지 않습니다.

## 화면 계약

1. 착공과 준공은 같은 고정열(단계/예정일/실제일/지연 여부/지연사유)로 비교합니다. 신고·연기신고·재개/변경준공 예정일과 세부내용은 바로 아래 단계/항목/내용 표에서 모두 확인합니다.
2. 본PF는 실제 원장에 있는 실행 여부/실행일/지연 여부/사유/세부내용을 표시합니다. 없는 PF 예정일을 만들지 않습니다.
3. 공사 전체 지연과 중단·재개를 구별하고 실제 지연사유·중단일·재개예정일·중단사유·세부내용을 표시합니다.
4. 공정률은 기준일·계획·실제·차이를 정렬된 표로 보여주고 수시 기록/공정 이력을 유지합니다. 계약·책임준공 약정과 대출 만기는 별도 표에서 독립 원장을 읽습니다.
5. 합계 33개의 실제 입력값을 조회에서도 빠짐없이 확인할 수 있어야 합니다. 미입력/명시적0/기존 비일자 원문을 보존하고 새 값을 생성하지 않습니다.
6. 최초 일괄작성은 전체 수정 버튼1개, 각 업무 수정은 같은 33필드 폼의 해당 fieldset에 초점을 둡니다. 값의 더블클릭만 알아야 수정할 수 있는 경로에 의존하지 않습니다. 기존 별도 인허가 상세는 변경하지 않습니다.
7. 일괄폼은 단계별 fieldset을 유지하고 label/value 열을 맞춥니다. DOM과 표시 순서는 같고 날짜·선택·숫자·장문의 원래 자료형·선택지를 보존합니다.

## 근거

Lazyweb 도구는 현재 세션에서 0개입니다. 공식 자료를 직접 확인했습니다.

- [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines): 비교할 값은 같은 열, 일정한 밀도·정렬과 작업 범위에 맞는 행동 배치.
- [Fluent Field](https://fluent2.microsoft.design/components/web/react/core/field/usage): 필드의 지속적인 이름과 값의 관계, 일관된 입력 정렬. 긴 필드는 줄바꿈과 검증 메시지 공간 보존.
- [USWDS Form](https://designsystem.digital.gov/components/form/): 관련 입력을 fieldset/legend로 묶고 DOM 순서·표시 순서를 일치시킵니다.
- [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/): 실제 값을 조회하고 같은 작업의 수정으로 바로 이동하게 합니다. 요약을 이유로 원래 필요한 값을 숨기지 않습니다.

## 실패검사와 수락

- 변경 전 C73에서 누락 8개와 33개 조회 대응, 고정 비교열, 업무별 수정 진입, label/value 행 정렬 실패를 고정합니다.
- 순수 검사에서는 원장/과거본/이력 불변, 33필드·기존 선택지/자료형·무변경 저장, 실패 전체 원복을 확인합니다.
- 실제 화면은 root가 제공하는 최종 정확 HTML의 1280/1440/1600/769/390에서 표·날짜폭·장문·수정 진입과 초점·저장/취소·오류·재접속을 별도로 검사합니다. 준비 오류와 제품 오류를 구분하고 과거 C73 결과를 새 구현 통과로 사용하지 않습니다.

## 구현과 현재 검증 상태

- 현재 정식의 실제 캡처 `.build/review130-20261028/screenshots/before-construction.png`를 직접 열어, 4개의 문장식 요약과 공정/약정의 기존 표현을 확인했습니다.
- 착공·준공 고정열2행+보조6행, PF5값, 전체지연/공사중단·재개7값, 공정3값, 약정4값을 표로 정렬했습니다. 원서식 비공정25+전체지연1+공정2+기준일1+약정4=33입니다. 공사 그룹26에는 전체지연이 이미 포함되므로 다시 더하지 않습니다.
- `review130-construction-display`의 C73 RED는1통과/7실패였습니다. 최초 8개 조회 누락과 새 고정열·수정 진입·정렬 계약의 부재를 구분합니다. 장문/비일자 원문은 별도 RED1→GREEN을 확인했고 유효한 ISO 날짜에만 고정 날짜폭을 적용합니다. 여러줄 사유는 줄바꿈을 보존합니다.
- 같은 공정 흐름에서 viewer의 차트/이력에 추가·수정이 노출되고 폼 제출 직전 사업/권한/활성 상태가 재검사되지 않는 결함도 발견했습니다. root 승인 후 RED4를 고정하고 진입/조회 버튼/콜백만 교정했습니다. 공정 계산·기록ID·과거본·삭제정책은 바꾸지 않습니다. 정상 다른 사업의 무관한 변경은 저장을 차단하지 않습니다.
- 자식 공정폼 취소에서 사업이 바뀌거나 삭제된 과거 부모를 다시 여는 반례도 RED1로 고정했습니다. 정상 부모 복귀를 유지하고 소실/전환된 부모는 재생성하지 않습니다.
- 현재 신규18조건이 통과했습니다. 기존33필드 저장/원문/실패16·선택 소비자13·기존 필수표시30조건도 통과했습니다. 순수 검사는 화면 정렬의 실제 완료를 뜻하지 않으며 최종 정확 후보로 native 검수를 대기합니다.
- 보고서 담당에게 독립 읽기 검토를 요청했습니다. 33개 원필드의 역할, 실제/예정/변경 예정, 착공 재개/공사중단 재개, 약정/실제 구분에 새 의미 오류가 발견되지 않았습니다. 이 판단은 실제 클릭/저장/화면/빈값의 수락을 대신하지 않습니다.
