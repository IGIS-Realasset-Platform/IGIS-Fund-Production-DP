# REVIEW129 — 보고서 원천·입력·저장·출력 연결 검수

대상은 RPT129-04·FORM129-06·UX129-07입니다. 정식 기준선 v0.12.8 C66에서 시작했으며, 구현·순수검사·정확 후보 화면·실제 회원/DB·출력·게시를 각각 판정합니다. 전체 플랫폼 완료 선언이 아닙니다.

## 독립 원천과 기준

- 앱 전용 스키마의 승인된 가상 A·B·C 현재값을 읽은 원천 지문은 77513897c2be762f3f1d93a322f40da47f5910092136dd1363336db8e8e0d44c, 원장 revision34/MD5 6838bc19114ea96d076cc5257b70b5c0입니다. 과거 보고서의 중복 payload/reportSnapshots만 원천 추출에서 명시 제외했고 실제 보관본 보존은 별도 DB 지문 검수 대상입니다.
- 값이 있는 필드만이 아니라 미입력·명시0·날짜 미발생도 대조합니다. 현재값·보고 기준일 당시값·사업비 확정시점·보고서 전용 수정본은 서로 다른 기준입니다. 원금액을 임의 배분하거나 누락을 다른 사업값으로 채우지 않습니다.
- [공식 제1호서식](https://www.law.go.kr/flDownload.do?bylClsCd=110202&flSeq=158641893&gubun=)의 칸·금액단위(억원)·면적단위(㎡)·일자/기간을 확인했습니다. 서식에 지분율 칸은 있으나 출자비율의 계산법을 별도로 강제하는 내용으로 해석하지 않았습니다. 현 플랫폼 출자 원장은 금액/합계로 지분율을 표시하고 수기비율 입력을 제공하지 않습니다.
- [WHATWG 입력 정의](https://html.spec.whatwg.org/multipage/input.html)와 [W3C 레이블](https://www.w3.org/WAI/tutorials/forms/labels/)에 따라 날짜·숫자·비율·금액·메일·전화/식별문자를 구별합니다. 전화/계좌/사업자번호·코드는 숫자처럼 보여도 계산값으로 강제하지 않습니다.

## 구현

1. **보고서 평문값의 입력 도구**
   - 단일 날짜·수치·메일·전화 셀에만 알맞은 도구를 씁니다. 날짜의 ISO 입력과 서식 점표기, 금액의 원 단위와 화면 억원 단위를 구별합니다.
   - 합성 라벨·복수 원천·인쇄 체크칸·고정문구·기존 비표준 원문은 문자 편집을 유지합니다. 모든 표시를 무조건 전역 값으로 분해하지 않습니다.
   - 같은 날짜/수치를 다시 확정할 때 서식 차이 때문에 허위 변경을 만들지 않습니다. 반복행의 단일 입력은 실제 업무명과 필드명을 접근성 이름으로 제공합니다.
2. **원문과 콜백**
   - 변하지 않은 기존 선택 원문·미확정 숫자/비일자 문자·불리언 원타입·선행0을 다른 필드 수정 때문에 소거하지 않습니다. 실제 새 값은 계속 검증합니다.
   - 숫자 공백은 null, 명시0은0으로 구별합니다. 보고 메일의 새 잘못된 주소를 저장하지 않습니다.
   - 보고 참여자·진행경과는 저장 직전 현재 프로젝트/대상 ID/열 때 원문을 다시 확인합니다. 삭제/교체된 옛 객체에 감사만 남기거나 새 항목으로 바꾸지 않습니다.
   - 이력의 기존 빈 상태·접수번호0은 신규 기본값으로 바꾸지 않습니다. 진행경과의 기존 비표준 일자·0 원문도 보존합니다. 새 제출 상태/새 날짜의 필수검사는 유지하고 변경 없는 재저장은 감사이력을 만들지 않습니다.
3. **좁은 셀의 일시적 입력 폭**
   - [AG Grid 공식 Popup Editor](https://www.ag-grid.com/javascript-data-grid/cell-editors/)처럼 편집기만 셀보다 크게 표시합니다. 기존 input/span·적용/취소·키보드·버퍼를 그대로 재사용합니다. 새 모드·드래그·하단 편집표를 만들지 않습니다.
   - 활성 reportCell에만 고정 표현/가독 폭을 적용하고 원래 높이의 빈 자리로 행·열·페이지를 유지합니다. 우측/하단에서는 편집기만 화면 안으로 이동합니다. 프린트 원본 CSS/DOM에는 적용하지 않습니다.
   - 보고서 가로 스크롤을 프로젝트/유형/기준별 식별자로 기존 복원 경로에 등록합니다. 모바일 취소 후 수평 위치가 초기화되던 연결 반례를 별도 검수합니다.

수정 제품은 src/report.js와 src/report-editor.css입니다. 법정 서식 생성 src/report-form.js 지문 e3b65cfddfd5d4b3ce84a4c88c6e18bad15179e0a58d00f905485999da4b6891, 원본 출력 CSS src/report.css 지문 db6bb5c2c549186af55e7704ed619b0c26bdc38c4934ca718e99fe5a20987c05는 유지했습니다.

## 실제 화면 확인 범위와 준비 오류

- 불변 C67의 좁은 인허가 일자 셀에서 달력 입력 폭66px로 월/일이 잘리고 원행 높이가 약43→98px로 늘어나는 모습을 실제 PNG로 확인했습니다. 더 넓은 날짜 셀의 통과를 좁은 셀에 승계하지 않았습니다.
- 같은 C67에 보고서 JS/편집 CSS2개만 치환한 임시 후보에서 입력 폭180px, 원 TD 폭/높이 보존을 확인했습니다. 최종 통합본 수락은 아닙니다.
- 임시 후보의 모바일 취소 검수에서 원 보고서 가로 스크롤이0으로 초기화되는 반례를 추가 확인했습니다. 식별자 등록 수정 후 정확 최종본 검수는 별도로 수행합니다.
- 원천 추출은 현재 프로젝트용 SELECT이므로 전체 workspace 응답에 필요한 비업무 배열3개만 모의 응답에 명시 보충했습니다. 프로젝트 값과 원천 지문은 바꾸지 않았습니다. 모의 응답 준비 실패/지문 오기/셀 ID 인코딩 선택자 실패는 제품 오류/통과로 세지 않았습니다.
- 집중검사의 옛 분기대출 자료가 현재 테스트 입력을 덮던 준비 문제와 더티 가드가 같은 화면 재조회까지 막던 테스트 진입 문제는 해당 fixture/동작만 분리했습니다. 날짜/금액/원문 보존 기대는 약화하지 않았습니다.

## 최종 판정 경계

정확 C70의 ABC×4종 reader는12/12, 날짜·수치·메일·장문의 실제 편집은1600/390px에서8/8 통과했습니다. 원래 셀 폭/높이·취소 후 포커스·가로 스크롤·원장 전체 불변을 확인했고 실제 원장 행값290개를 화면과 직접 대조했습니다. 실제 원격 요청·DB 쓰기·페이지/콘솔 오류는0입니다. 처음 모바일 실행의 펼친 메뉴가 셀을 가리던 준비상태와, 메뉴를 닫고 입력한 최종 수락상태는 별도 결과로 보존했습니다.

PDF skill의 생성 marker를1회 실행한 뒤 측정된 실제 reader iframe DOM·기존 인쇄 CSS 그대로12개/48쪽을 각각1회만 내보냈습니다. 출력 페이지수·원장값 텍스트·한글 검색/PUA0·소스 불변 검사를 통과했습니다. 보고서 담당이44쪽과 입력 화면8개를 직접 열었고 독립 검토자가 B/C 취소·완료4쪽을 직접 확인해48쪽 전체가 실제 이미지 관측 범위에 들어갑니다. 행/페이지 잘림·문자 깨짐·페이지 이탈은 관측되지 않았습니다. 고정서식의 좁은 날짜 칸 줄바꿈과 표를 다음 페이지에 유지하기 위한 하단 여백은 그대로이며, 이번 입력 도구 교정을 인쇄서식 재설계로 확대하지 않았습니다.

취소·완료6개 보고서의 사유 체크 공란은 현재 원DB의 기존 자유 원문이 법정서식의 표준 선택문구와 일치하지 않는 경우입니다. 이를 추측해 표준 선택으로 승격하지 않고 세부 사유에 원문을 유지합니다. 현재 reader/PDF의 원문 사유·발생일·상세 사유 보존과 임의 체크 없음42/42를 추가 대조했습니다. 따라서 공란을 곧 원문 누락으로 판정하거나 자동 체크하지 않았습니다.

C70 HTML 지문은 be8155fd2a28989008adb50e26769d0786ce58e29564b4d01eda2521afcac8bc, 중간 후보 C71은 cbd594f47aaf784966e2ff800df3f1167475029379ca75a8922b3c0d1f13bc3e입니다. 전체 바이트 대조에서 툴팁의 편집 중 자식 검사71바이트 한 곳만 달라졌고 보고서 JS·원서식·인쇄 CSS·편집 CSS4개는 모두 같습니다. PDF12개는 C70에서 생성된 원본 지문을 유지하고 C71 소스 동등성으로 연결하며, C71에서 재생성했다고 표시하지 않습니다. 중간 C71의 실제 reader 재검수를 별도로 수행한 것으로 표시하지 않습니다.

최종 후보는 C72(d3e9d0f036687bf8e4754e135d8e20a5943752235c7c9bb411ac1b89b90b1603)로 이어졌습니다. C72의 최종 reader/입력 확인은 별도 실제 실행으로 판정하며 PDF를 다시 생성하지 않습니다. 연결 검사의 CSS 문자 해석 준비 오류는 제품·출력 결함으로 세지 않았고, 올바른 내장 문자열을 읽은 뒤 연결 검사를 통과했습니다.

실제 DB 저장/재접속/원값 복원·과거 payload 보존은 실제 회원/서버 검수 기록으로 따로 판정합니다. 다른 실제 회원·서식의 법적 수리 여부·자연 예약 실행·680개 정적 입력 후보의 모든 동적 분기를 이 문서의 원천 대조/출력 검수로 수락하지 않습니다.
