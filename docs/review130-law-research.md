# REVIEW130 법령 날짜·판본 비교·지방 문서 근거

기준선은 2026-10-28 정식 v0.12.9 C73(소스 `3a74775b99b7d51a8f21c7bb3eead5fb8f317f74`)입니다. 이 문서는 법령 담당의 조사·실패검사·연결 기준이며 전체 화면이나 새 배포의 수락 기록을 대신하지 않습니다. 업무 DB·기존 서비스·다른 스키마·Auth·법령 원본은 이 조사에서 변경하지 않았습니다.

## 최근30일의 기준

확정된 정책은 실제 모드에서 **현재 한국시간의 오늘과 앞선29개 달력일**, 공포일 기준입니다. 수집자료의 `dataDate`, 최초 발견일, 시행일을 공포일 대신 사용하지 않습니다. 과거 판본·수집 이력을 삭제하는 기능이 아닌 조회 조건입니다. 시행일 조회와 예정 조회도 같은 오늘을 끝점으로 사용하며, 샘플 모드는 당시 자료기준일을 유지합니다.

기존 구현은 자료기준일을 조회 끝점으로 사용했습니다. 독립적인8개 기대에서 오래된/미래 자료기준일·한국 자정·연도 경계·시행일 조회5개가 실패했고, 잘못된 날짜와 첫관측/시행일 혼동을 배제하는3개는 통과했습니다. 허용된 날짜 관련3곳만 교정한 뒤 같은8개가 통과했습니다. 예정 조회 끝점과 샘플 정책 보존2개를 추가한 `tests/review130-law-window.mjs`는10개를 구분합니다. 이것은 실제 브라우저/서버 수락과 별개입니다.

## 공식 비교 기능과 이 판본의 제공 여부

[법제처 API 목록](https://open.law.go.kr/LSO/openApi/guideList.do)은 법령 `oldAndNew`, 행정규칙 `admrulOldAndNew`를 제공하며 자치법규의 신구법 API는 같은 목록에 명시하지 않습니다. [신구법 본문 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=oldAndNewInfoGuide)는 판본 식별값과 공포일·번호를 받고, 실제 미제공은 별도 값으로 반환합니다. API 미제공을 모든 공식 웹 기능의 미지원으로 확대하지 않습니다.

반대로 공식 웹페이지에 공통으로 포함된 ‘신구조문비교’ 설명이나 공개 JavaScript의 함수가 있다는 사실도 해당 판본의 실제 비교표 제공을 증명하지 않습니다. [법제처의 기능 안내](https://moleg.go.kr/board.es?act=view&bid=0048&list_no=135562&mid=a10501000000) 역시 행정규칙의 표·그림 자료에 대한 제한을 구별합니다.

두 원문 공개 HTML과 실제 공식 API 본문의 동일ID·날짜·번호를 직접 확인했습니다. 일련번호 숫자의 대소로 선후를 추측하지 않았습니다. 관리목록의 이력에서 같은 공포일/시행일의 후보가 둘 이상이면 임의로 하나를 고르지 않습니다.

CUA는 이 작업에서 연결된 브라우저 목록이 없어 준비 단계에서 중단됐습니다. 계정 미연결로 해석하거나 계정·설정을 다시 바꾸지 않았습니다. 이어 승인된 격리 Edge와 실제 공식 네트워크를 사용하는 `.build/review130/official-ordin-browser.mjs`로 확인했습니다. 익명 프로필이며 업무 앱·실회원 쿠키·업무 API를 사용하지 않았습니다.

- 개정 후 원문의 실제 조문이 로드된 최종 DOM에는 `법령비교`만 표시됐습니다. 공통 설명과 숨겨진 `조례비교(전체)`를 해당 판본의 제공 버튼으로 계산하지 않았습니다.
- 관측한 `법령비교`를 실제 클릭하면 공식 `lawBodyCompareInfoP.do`의 수동 선택창이 열렸고, 로딩이 끝난 뒤124개 검색목록이 나타났습니다. 두 판본이 선택된 정확한 신구대비표가 아니었습니다.
- 내부 공개 스크립트의 `ordinOldAndNew.do` 경로는 GET과 해당 스크립트의 POST 방식 모두404였습니다. 이 경로를 제품에 공식 대비표 주소로 추가하지 않았습니다.
- 최초 새 창 이벤트를 기다리지 않은 검사 준비와 로딩 중 창을 찍은 중간 증거도 보존합니다. 최종 네이티브 증거는 `.build/review130/official-ordin-1793166835666/evidence.json`이며 HTTP200만으로 전후표 확보를 선언하지 않습니다.

기존 제품의 `getOfficialLawDetail(comparison:true,beforeSequence,beforeEffectiveAt)`와 `compareOfficialLawDetails`를 실제 공개 샘플 API에서 실행해 두 공식 본문과 부칙을 확보했습니다. 결과는 동일ID의 `verified-version-whole-body-comparison`이며 **전체 본문/부칙2개의 가공 대비행**입니다. 이를 ‘공식 제공 신구대비표’ 또는 ‘변경조문2개’라고 바꾸어 부르지 않습니다. 원증거는 `.build/review130/seoul-ordin-comparison.json` SHA `553ab356f8061c8e8d5a16406c285d80acc7ac4ae9ff0820b2e1d300a9cef264`입니다. 프로젝트 적용 확정은 false이며 별표 첨부파일 내부 문구까지 비교한 것은 아닙니다.

### 연결·표시 계약

- 실제 공식 대비표 링크를 확보한 경로는 그 직접 링크와 원문을 유지합니다.
- 공식 대비표가 없어도 정확한 두 판본이 유일하면 `개정 전 원문`/`개정 후 원문`을 구분합니다. 같은 법적 판본의 본문 해시 재관측을 이전 법 개정과 혼동하지 않습니다.
- `canCompareVersions(change,effectiveAt?)`는 본문 대비를 **요청할 수 있는지**만 반환합니다. 이미 비교 완료 또는 법적 적용이 확정됐다는 뜻이 아닙니다.
- 요청 가능한 경우 목록의 `변경 전·후` 한 번으로 기존 단일 창에서 자동 조회합니다. 별도 불러오기·두 번째 팝업·수집 운영 상태표를 추가하지 않습니다.
- 응답의 실제 target·판본·시행일·공포정보와 두 판본의 공식ID를 대조합니다. 다른 판본·다른 관할·늦은 응답·프로젝트 전환을 성공으로 덮지 않습니다.

`tests/review130-law-comparison-links.mjs`는 독립적인 판본/링크/단일 조회/동일판본 재관측/잘못된 응답 반례를 검사합니다. 초기 `URLSearchParams` 미주입 및 VM 배열 prototype 차이는 검사 준비 문제로 구별하며 제품 반례로 세지 않습니다.

## 지방 문서의 종류와 실제 지원 범위

지방자치단체가 법률을 제정한다고 표시하지 않습니다. 조례·규칙과 지방행정규칙, 개별 계획결정·고시·공고를 자료 종류별로 구별합니다. ‘고시’라는 제목만으로 모든 문서가 같은 효력이나 같은 적용범위를 가진다고 판단하지 않습니다. [법제처 행정규칙 안내](https://www.law.go.kr/LSW/flDownload.do?flNm=%ED%96%89%EC%A0%95%EA%B7%9C%EC%B9%99+%EC%97%85%EB%AC%B4+%EC%A2%85%ED%95%A9%EC%95%88%EB%82%B4%EC%84%9C&flSeq=22317830)는 일반적인 행정사무 기준과 상위법의 위임에 따른 법령보충적 행정규칙을 구별합니다. 개별 문서의 대외적 효력은 명칭만으로 자동 판정하지 않습니다.

[공식 ordin 목록 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinListGuide)의 knd는30001조례·30002규칙·30003훈령·30004예규·30006기타·30010고시·30011의회규칙입니다. 공개 샘플 호출에서 `건축` 검색과30003/30004/30010으로 각각4/1/1건을 실제 반환받았습니다. 예규 `서울특별시 친환경 건축 기준`(487451), 고시 `서울특별시 녹색건축물 설계기준`(2126163), 교육청 개축심의 운영 훈령이 포함됐습니다. 검색 가능성을 현재 사전 등록/정기 확인 완료로 바꾸지 않습니다.

[공식 admrul 목록 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=admrulListGuide)도 종류별 코드를 제공하지만 지자체 모든 사업별 문서를 포괄하는 API라는 근거는 아닙니다. [토지이음의 데이터개방 목록](https://www.eum.go.kr/web/op/sv/svItemList.jsp)은 자료별 CSV/SHP/PDF/API와 각 갱신주기를 구별합니다. [공식 서비스 설명](https://www.eum.go.kr/web/am/visit.jsp)도 결정고시·지형도면고시·실시계획인가고시와 필지/계획 열람을 구분합니다.

기존3종 API의 실제 종류 보존과 문구를 새 DB 스키마 없이 교정했습니다. 기존 행을 임의 UPDATE하지 않으며 이후 명시적 등록 시 공식 본문에서 확인한 kind만 source JSON에 선택 저장합니다. 미확정 코드를 조례/기타로 생성하지 않습니다. 새로운 지방 공보/토지이음 수집은 서비스 승인·사용조건·공급자 식별자·지역/사업지 범위·정정/취소/폐지 계보·실패 복구·보관량을 확인해야 하므로 기존 활성376개를 신규 전국 문서 수집으로 확대하지 않습니다.

### 토지이음의 정확한 연결·이용 조건

공식 고시검색 경로는 [고시정보 목록](https://www.eum.go.kr/web/gs/gv/gvGosiList.jsp)입니다. 실제 공개 페이지를 읽어 고시제목, 광역시도/시군구, 고시일, 담당/고시기관, 고시번호, 결정고시/지형도면고시/실시계획인가고시 조건의 **POST 검색폼**을 확인했습니다. 근거 없는 GET 검색조건을 붙이지 않습니다. 앱의 보조 `지역 고시·도시계획 검색`은 이 고정 공식 검색창을 새 탭으로 열며 앱 검색어나 실사업지를 자동 전송하지 않습니다. 기존 검색·관리법령 추가 API와 주기수집은 그 동작으로 변경되지 않습니다.

데이터개방의 `고시정보`는 dataCd008입니다. 해당 API 안내는 별도 **연계신청서 작성 → 공식 담당 메일로 발송 → 연계KEY/매뉴얼 수신** 절차이며 주말·휴일 제외3일 내 발급을 안내합니다. 기존 법제처나 공공데이터포털 인증값을 재사용할 수 있다고 가정하지 않습니다. 신청·메일 발송·인증값 발급은 이 작업에서 하지 않았습니다.

같은 항목의 CSV는 월간 갱신, 최신 작성일2026-10-16·전국 ZIP22.88MB·제공/원문기관 각 시군구를 명시했습니다. 해당 자료는 공공누리 출처표시 조건을 안내하고 마크 미부착 자료는 자유이용 대상으로 보지 않는다고 명시합니다. 파일 다운로드에는 활용 목적 입력 절차가 있으며 실제 파일을 내려받지 않았습니다. 전국 CSV를 일일 새 고시 수집으로 간주하지 않습니다. 우리 서버의 이 원천 수집·예약 연결은 여전히0입니다.

원천 페이지는 EUC-KR이므로 UTF-8로 읽은 최초 도구 출력의 깨짐을 원자료 오류로 판단하지 않았습니다. 올바르게 디코드한 공개 메타만 `.build/review130/eum-public-page-metadata.json`, `eum-notice-dataset-metadata.json`에 보존합니다. 공식7종 목록/본문의 동일ID 대조는 `official-ordin-kinds.json`에 남깁니다.

## 구현·집중검사의 현재 범위
