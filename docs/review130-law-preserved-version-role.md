# 미확정 과거 판본 보존과 현재 확인 근거의 분리

2026-10-29 · LAW130-R1~R7의 연결 검증입니다. 일반 이용자 화면에 운영 상태나 기술 설명을 추가하지 않습니다.

## 실제 원인

앱 전용 스키마의 최신 자료를 읽기 전용으로 확인한 결과, 당일 확인된 네 관리법령에는 공식 식별자·본문 지문이 없는 과거 판본과 새로 확인된 공식 판본이 함께 있었습니다. 과거 판본의 `current`·`scheduled` 값을 현재 확인 완료의 증명으로 사용하면 안 됩니다. 반대로 이 값을 일괄 `historical`로 바꾸거나 과거 원문을 삭제해서도 안 됩니다.

이 조회는 네 법령의 공개 식별자·날짜·자료형과 보존 표식 유무만 확인했습니다. 본문·계정 비밀·사업비를 조회하지 않았습니다. 기존 자료에는 해당 역할을 구분하는 보존 표식이 없었습니다.

## 교정 경계

1. 공식 제공자의 새 응답은 각 관리법령의 처리 안에서 먼저 검증합니다. 현재·시행예정 판본의 정확한 공식 식별자, 원문 URL, 날짜, 당일 본문 지문이 하나라도 불완전하면 그 관리법령만 실패로 남깁니다. 다른 정상 항목의 진행은 보존합니다.
2. 이전 자료에 실제로 존재했던 미식별 판본만 원래 객체의 전체 지문으로 따로 연결합니다. 원판본의 날짜·상태·본문 및 미입력/0 값을 바꾸지 않습니다.
3. 서버 저장 직전에 이 연결이 이전의 정확한 같은 원판본과 일치하는지 다시 확인합니다. 새 미식별 응답, 변조한 과거 원문, 식별된 새 판본을 보존 예외로 위장하면 거절합니다.
4. 공식 식별자가 확인된 새 판본은 정상 검증을 우선 적용합니다. 과거의 보존 연결로 새 응답의 누락 검증을 건너뛰지 않습니다.
5. 정확한 완료 ID 집합, 한국 날짜, 관리범위, 처리 잠금, 원자 저장, 재시도·대기 규칙은 유지합니다. 근거가 부족한 구형 부분결과는 새로 조회하는 안전한 경로를 사용합니다.

## 검증 구분

`tests/review130-law-preserved-role.mjs`는 실제 네 자료의 공개 메타데이터 형태를 독립 모형으로 만들었습니다. 기존 자료를 변경할 수 없게 고정한 상태에서 원문 보존, 불량 새 응답의 개별 실패, 정상 판본 우선 검증, 같은 날 재사용, 실제 서버 저장 검증과 위조된 보존 연결 거절을 실행합니다. 최초 3통과/9실패에서 교정 후 12통과로 바뀌었습니다.

집중 회귀의 정상 제공자 모형은 실제 제공자와 같은 64자리 본문 지문·정규 확인시각·필수 판본 정보를 준비합니다. 과거 미확정 원문에 식별자나 본문을 만들어 넣지 않습니다. 완료된 같은 날의 결과를 다시 수집한다고 기대하던 과거 시험은 별도의 다음 날 관측으로 구분하며, 기존 사건과 실제 공포일은 보존합니다.

서버 및 조회 소비자의 구체적인 지문과 최종 회귀 결과는 `review130-law-collection-recovery-verification.json`의 후속 보존역할 절에 기록합니다. 로컬 모형 통과는 실제 배포·복구 성공이 아닙니다. 실제376개 복구와 이후 자연 예약 확인은 담당 루트의 배포 후 별도 검증으로 남깁니다.
