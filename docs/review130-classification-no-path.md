# REVIEW130 · 사업비 분류 수정의 경로 강제 제거

분류 수정은 회사 관리분류와 실제 소속을 바꾸는 업무입니다. 새 근거파일 경로를 입력해야만 분류할 수 있었던 동작을 제거합니다. 계약·문서의 원본 경로와 인허가 신청·진행자료 경로는 이 변경의 대상이 아닙니다.

`src/cbs-purpose.js`의 분류 함수와 폼 3줄만 교정했습니다.

- 분류 수정 폼에서 `분류 근거 경로` 입력을 제거합니다.
- 경로를 모른다는 이유로 정상 분류를 거부하지 않습니다.
- 기존 분류의 `evidence`와 원래 행의 `sourcePath`는 경로 없는 수정으로 지우지 않습니다.
- 제거된 폼의 오래된 숨은 `evidence` 값을 새 입력으로 사용하지 않습니다.
- 기존 API 호출자가 명시한 경로는 계속 보존할 수 있습니다.

대분류·명칭의 필수 검증, 실제 owner, 열린 뒤의 대상·사업 변경 검사, 원단위 금액·고정본·계약/VAT 범위·확정총액 보호, 분류·감사기록을 유지했습니다. 새로운 입력칸이나 화면 구조는 추가하지 않았습니다.

독립 `tests/review130-classification-no-path.mjs` 14조건은 변경 전 분류 모듈의 불변 사본에서 5통과·9실패, 현재 소스에서 14통과입니다. 이름/분류 수정, 경로 공란, 기존 경로, 제거한 숨은 필드, 명시 legacy 호출, owner, 삭제·교체·다른 사업, 취소 무쓰기, 격리 cloud 503 원복, 보호범위와 드래그 분류의 소속·원금액 결과를 구별합니다. 드래그 비교는 분류·소속·금액 소비자의 대조이며 실제 포인터 드래그 검수로 확대하지 않습니다.

기존 `v0117-cbs-purpose`의 빈 경로 거부 1조건만 최신 사용자 지침으로 대체했습니다. 원금액·확정본·실패 원복·중복 대분류의 기존 단언은 유지했습니다. 해당 모듈, 확인분류 이동, 사업비 하위분해, 비용 부모복귀의 인접 4모듈은 모두 종료코드 0입니다.

초기 합성 준비의 존재하지 않는 다른 사업 ID와 빠진 cloud 화면 배열은 준비 문제로 보존하고 실제 다른 사업과 표준 상태 배열을 넣어 검사했습니다. 실제 DB 쓰기는 0회입니다. 후속 C84 정확 생성본에서 PC·390px 정상/503 실제 폼 4흐름을 통과했으며 `docs/review130-native-C84.md`에 연결했습니다. 실제 서버·DB 검수로 확대하지 않습니다.
