## 현재 실제 흐름

- `A.audit`의 제목 있는 업무 변경이 공유 `state.notifications`에 알림을 추가합니다. 별도의 담당자 수신목록이 없으며 현재 프로젝트를 읽을 수 있는 직원이 작성자 자신을 포함해 받습니다.
- 일반 만기/일정 도래 알림을 자동 생성하는 별도 코드 경로는 현재 확인되지 않았습니다. 일정 변경 사실은 일반 audit 알림이 될 수 있습니다. 이 부재를 승인된 신규 기능 요구로 추측하지 않습니다.
- 분기 확인은 서버 예약 작업이 `quarterly_tasks`에 생성하며 `(project_id,quarter_key)` 고유조건으로 중복을 막습니다. 완료/정정은 사업비 시점 기록과 연결되며 개인 알림 삭제와 다릅니다.
- 법령은 명시적 프로젝트 구독 이후·플랫폼 도입 이후의 변경을 현재 조회권한으로 걸러 읽기 시 계산합니다. 알림 ID는 기존 프로젝트+변경 ID 지문을 유지하며, 실제 같은 판본으로 검증한 원본 멤버의 개인상태만 현재 대표 알림으로 연결합니다.
- `GET/PATCH /api/notifications`는 앱 전용 스키마와 기존 로그인/프로젝트 역할을 사용합니다. `viewer`도 자기 읽음·삭제·복원은 가능하며, 개인상태는 `(user_id,notification_id)` 원자 UPSERT에 저장합니다. 알림 조작은 작업공간 revision이나 업무자료를 갱신하지 않습니다.
- 과거 공용 `dismissed`는 보존하며 누가 삭제했는지 모르는 기록을 특정 직원에게 재배정하지 않습니다.

## 확인된 연결 문제와 최소 교정

교정 전 GET은 개인상태·분기·법령만 반환해, 다른 직원이 생성한 일반 알림은 오래된 클라이언트 작업공간에 나타나지 않았습니다. 클라이언트의 삭제된 사업 필터도 서버의 생존 사업 필터와 달랐습니다. GET에 권한으로 걸러진 작은 `notices`·`projectIds`를 호환 추가하고, 작업공간 밖 캐시에 반영했습니다. 빈 배열은 빈 범위로 존중하며 옛 작업공간으로 되살리지 않습니다. 사용자가 미저장한 로컬 알림은 권한 범위 안에서 보존합니다. 상위 `projectId`만 있는 기존 알림은 클릭 목적지에도 같은 사업을 적용하고, 상위와 target의 사업ID가 다르면 둘 다 권한이 있어도 모순된 알림을 표시하지 않습니다. 원래 알림 객체는 바꾸지 않습니다.

분기 ID는 생성식상218자까지 가능하나 PATCH는 공통200자 ID 검사로 거절합니다. `quarterly:<허용 사업ID>:YYYY-Qn` 형태만 예외로 인정하고 실제 현재 허용 ID 집합을 다시 확인합니다. 대상·역할·수신범위는 확대하지 않습니다.

법령 변경 정규화는 구독마다 같은 배열을 반복 처리하므로 한 요청에 한 번만 계산하도록 옮깁니다. 알림 PATCH의 기본 형식은 비싼 업무/법령 조회 전에 확인합니다.
