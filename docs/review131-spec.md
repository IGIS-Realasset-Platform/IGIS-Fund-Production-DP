## 저장과 표시 기준

- 탭 전환은 저장이 아닙니다. 변경한 조건은 동일 초안의 추천에 자동 반영합니다.
- 사용자가 의도적으로 고른 항목·해제한 항목과 자동 추천을 구별합니다. 이미 등록된 기록은 새 후보로 생성하지 않습니다.
- 조건만 수정하는 저장도 허용합니다. 항목을 추가하는 저장에서는 조건과 추가 기록을 일괄 검증하며 일부만 남기지 않습니다.
- 지운 조건을 기존 프로젝트 기본값으로 되살리지 않습니다. 속성 자체가 없을 때의 초기값과 사용자가 저장한 공란·0은 다릅니다.
- 목록에는 현행 법령의 정식 절차명을 사용합니다. 조건은 절차와 별개이며 동일 절차의 조건이 늘어났다고 새 절차를 중복 생성하지 않습니다.
- 대상 판단을 위한 조건 미확인은 법적 비대상 판정이 아닙니다. 수치 기준은 확인한 현행 법령·별표·지역 조례 없이 만들지 않습니다.

## 보존·변경 제외

개별 인허가 상세 4탭은 사용자의 유지 지시에 따라 보존합니다. 기존 사업·금액·계약·부가세·확정본·보고서 분류, 다른 서비스·DB 스키마·공유 로그인 설정은 변경하지 않습니다. 실제 저장 검수는 기존 승인된 A·B·C 샘플에서 필요한 범위만 수행합니다. 기준 원본은 수정·재계산하지 않습니다.

## 역할과 완료 판정

수정 단위의 현재 채택안은 사업개요24입력의 구역 폼, 대출·출자·담보·보증·계약·문서·필지·분양·현안·유사사업의 기록별 폼입니다. 기존 비용행은 독립 금액·사유의 입력 단위를 유지하며 새 표 전체 저장 모드를 만들지 않습니다. 공사·보고서는 기존 일괄 입력을 재사용합니다. 각 단위의 실제 수정 접근이 있는 경우에만 중복 셀버튼을 제거합니다.

추천의 조건과 목록은 같은 초안입니다. 명시적 공란·0과 속성 부재를 구분하고, 교통 지역과 대상범위·대공방어 구역과 법정 높이는 각각 함께 확인합니다. 입력 조건은 법적 의무를 자동 확정하는 증거를 대신하지 않습니다. 실무 약칭은 검색용이며 기존 기록의 이름·유형 ID를 임의 병합하는 근거로 쓰지 않습니다.

프런트엔드 담당은 두 탭·초안·폼을, 백엔드 담당은 순수 추천 규칙·조건 계약·법적 근거를, UX 담당은 실제 사례와 수정 단위를, 독립 QA는 반례·실제 동작·원자료 보존을 맡습니다. 수정 담당과 독립 검토자의 결과를 분리합니다.

현재 단계는 구현·집중 검수 중입니다. 명세 작성, 정적 검사, 자동검사, 실제 화면, 실제 DB·재접속, 최종 배포는 각각 별도로 기록하며 기존 전체 플랫폼의 미검증을 이번 범위의 통과로 지우지 않습니다.
