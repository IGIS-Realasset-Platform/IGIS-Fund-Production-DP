# REVIEW130 · 정상 입력 전환의 초안 소비

## 결함과 보존 범위

C83의 격리 브라우저 검수에서 100,000,000원을 직접입력 60,000,000원과 목록선택 40,000,000원으로 나눈 뒤, 다음 직접입력을 열면 이전 60,000,000원이 새 항목의 입력값으로 복구됐습니다. 이름만 입력해 저장해도 이전 금액이 새 행에 저장됐습니다. PC와 390px에서 같은 결함을 확인했으며 실제 DB에는 쓰지 않았습니다.

원인은 비용 입력을 받아 상위 화면으로 전환한 콜백이 `false`를 반환하는 방식과, 미완성 입력을 보존하는 공통 초안 기능의 결합입니다. `false`를 모두 성공으로 처리하면 검색조건·취소·오류 입력까지 잃으므로 그렇게 바꾸지 않습니다.

원금액·분해 합산·비용코드·과거 시점·계약·부가세·삭제 조건·회사 관리단위는 변경하지 않습니다. 표·열폭·화면 재생성·상위 펼침 상태의 별도 교정은 이 변경의 범위가 아닙니다.

## 공통 폼 계약

`A.form(..., {consumeOnTransition: true})`는 입력을 정상적으로 소비한 뒤 새 부모 폼 또는 조회 모달로 이동하는 소비자만 명시합니다.

- 정상 콜백이 `false`를 반환하고 이전 세션에서 다른 세션으로 전환돼야 합니다.
- 취소되지 않은 작업이어야 하며, 중앙 저장이 진행 중이면 성공 확인 후에만 소비합니다.
- 삭제할 키는 콜백 제출 시점에 고정합니다. 이후 사업·화면 문맥으로 다른 초안을 찾지 않습니다.
- `false`의 기존 의미를 유지해 추가적인 닫기·재생성을 하지 않습니다.
- 옵션 없는 전환, 같은 세션의 `false`, 예외, 503, 미저장 닫기는 기존 입력과 초안을 보존합니다.
- 이름·금액의 다음 새 입력은 공란이며, 확인된 0을 다음 행의 기본금액으로 만들지 않습니다.

기존 수정은 기존 금액을 표시합니다. 서버 실패 후 원래 입력값·원금액·이력의 보존은 새 입력의 빈 초기값과 별도로 검사합니다.

## 소비자별 적용

| 소비자 | 적용 | 이유 |
|---|---|---|
| `cost-breakdown.openEntry` | 명시 옵션 | 초기 직접/목록 입력, 활성 하위 추가·수정이 성공하면 상위 구성으로 복귀합니다. |
| `cost-breakdown.showManager`의 최초 합계 전환 | 명시 옵션 | 성공한 전환의 사유·확인 초안은 사용을 마쳤습니다. |
| `cost-breakdown.openDelete` | 명시 옵션 | 삭제 사유를 저장한 뒤 상위 조회로 복귀합니다. 삭제 취소의 초안은 보존합니다. |
| 하위를 관리할 소유자 선택 | 유지 | 새 비용을 저장하는 입력이 아니라 선택 문맥입니다. |
| 법령·조례 검색, 지역 조례 조회 | 유지 | 다시 검색하거나 상위로 복귀할 때 조건을 유지합니다. |
| 인허가 추천 조건·후보 선택 | 유지 | 중간 단계 선택의 보존이 필요합니다. |
| legacy 인허가 연속입력 `flow.onSaved` | 검토 후보로 기록 | 실제 쓰기 뒤 다음 폼으로 이동하지만 인허가 ID별 독립 초안키를 사용합니다. 이번 범위에서 옵션을 일괄 추가하지 않았습니다. |
| 댓글·보고서·계약 등 일반 CRUD | 유지 | 정상 콜백은 `true` 또는 일반 반환입니다. 권한·취소·무변경의 `false`는 소비 대상으로 바꾸지 않습니다. |

정적 `return false` 검색은 후보를 찾는 방법이며 그 개수로 정상 전환 소비자의 전수 검증을 선언하지 않습니다.

## 검증 기록

`tests/review130-form-transition-drafts.mjs`의 18조건은 변경 전 core/cost 불변 사본에서 8통과·10실패, 현재 소스에서 18통과입니다. 실제 금액 재사용, 0/공란, 다른 초안, 제출 당시 키, 동기/비동기 폼·모달 전환, 옵션 없는 전환, 같은 세션, 예외, 미저장 닫기, 중앙 저장의 성공/503, 기존 0원 수정, 비용 최초 전환·추가·삭제를 구별합니다.

초기 시험의 누락된 `sourceLoad`와 로컬 저장실패 모의는 준비 문제로 별도 보존했습니다. 현재 서버실패 검사는 설치·불러오기한 실제 cloud 계약과 격리 503 응답을 사용합니다. 이를 실제 서버 인증·DB 접근 검수로 확대하지 않습니다.

관련 기존 회귀 8모듈을 실행했고 모두 종료코드 0입니다. 최초 전환·삭제에 옵션을 추가한 뒤 비용 폼 6조건·부모 복귀 15조건·인허가 저장 전환 18조건도 다시 통과했습니다.

후속 C84 정확 생성본에서는 원래 실패한 비용 흐름을 PC·390px에서 다시 실행해 2/2 통과했습니다. 새 금액칸을 검사 코드가 강제로 지우지 않고 공란·null, 실패 원복, 재접속을 확인했습니다. 증거는 `docs/review130-native-C84.md`에 연결했습니다. 이를 정식 배포나 전체 화면 검수 완료로 확대하지 않습니다.
