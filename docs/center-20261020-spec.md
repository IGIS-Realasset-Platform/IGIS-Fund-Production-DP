## 서버·브라우저 공통 계약

기존 workspace/project-access API와4MB/CAS 계약 유지. 아래 자료는 서버 소유 별도 테이블이며 구형 workspace PUT가 덮지 않습니다. 모든 사용자 API는 기존 세션·allowlist·동일Origin 검사를 재사용하고 `Cache-Control: no-store`를 적용합니다. 오류는 `{error,message}`/401·403·409·422·503이며 민감한 내부 원인을 응답에 넣지 않습니다.

### 개인 알림 `/api/notifications`

- GET: `{states:[{notificationId,readAt,deletedAt}],tasks:[...quarterlyTaskMetadata],alerts:[...lawReviewAlert]}`. 상태는 현재 회원 것만 반환. 업무 알림은 기존 안전한 프로젝트 원장에서 생성하고 법령 알림은 명시 구독 이후의 신규 변경과 읽을 수 있는 현재 사업만 연결합니다.
- PATCH JSON `{notificationId,action:'read'|'delete'|'restore'}` → `{state:{notificationId,readAt,deletedAt}}`. 원업무 삭제나 완료 아님. 읽을 수 있는 사업에서 실제 생성 가능한 알림/서버과제만 허용. viewer도 개인상태 수정 가능.
- 브라우저는 popup을 열 때마다 소형 GET으로 개인상태·과제·법령 알림을 갱신하고 PATCH만 수행합니다. 낙관 갱신 실패시 행·선택·scroll 복원. legacy dismissed는 그대로 보존하고 개인 귀속을 추정하지 않습니다. 초기 상태를 아직 읽지 않았다면 숫자0이나 안 읽음0으로 표시하지 않습니다.

### 기준정보 `/api/reference-data`

- GET `?kind=partners` → `{version,checkedAt,source,groups,market}` (표에 필요한 공개 범위만). `?kind=partners&companyKey=...` → `{company}` 상세. GET `?kind=laws` → `{status,checkedAt,lastSuccessAt,records,changes}`.
- 인증 후 읽기전용. source snapshot 내부 데이터는 로그인 HTML/Git에 넣지 않으며 앱 전용 DB의 reference_snapshots에 보관합니다. 내부 companyRegistry·메모와 합치지 않습니다. 업체 탭/상세에서만 로드합니다.
- 최신 반영본은 `raportal-dom-20261020-v2`입니다. 2026-10-20 16:56:40 한국시간 기준 원문150업체·수주158·뉴스245·공식 시드 코멘트11·확인단가5를 대조했고, 직원이 입력한 댓글 본문이나 미확인 신용평가사·기준일을 추측해 복사하지 않았습니다. 07:53:36Z의 중간 재대조 기록과 07:56:40Z의 최종 원문 확인·저장을 구별합니다.

### 소유자 명세 기능권한

### 사업비 시점 `/api/cost-snapshots`

- GET `?projectId=...` → `{snapshots:[metadata],tasks:[...]}`. `&id=...` → `{snapshot:{metadata,payload}}`. payload는 해당 버전 원단위 금액·코드·계약·비교기준이고 메타에 본문을 누적하지 않습니다.
- POST `{projectId,requestId,expectedRevision,kind:'quarterly'|'event'|'approvedBudget',quarterKey?,asOfDate,label,reason,correctsId?}`. 서버 현재 workspace에서 payload 구성. editor는 quarterly/event, approver/admin만 approvedBudget. quarterly는 존재하는 해당 확인과제 필요. captureAt은 서버시각, asOfDate는 담당자 확인일 기준 입력이며 과거 분기말 당시금액이라고 표시하지 않음.
- 동일 requestId는 동일결과, 다른내용 재사용409. 낡은 expectedRevision409. 정정 새 버전, 기존본문 UPDATE/DELETE 금지. quarterly는 해당과제만 완료, event는 정기과제를 완료하지 않음. snapshot이 최근승인예산을 임의 교체하지 않음.

### 지역별 확인할 조례 `/api/law-regional` — CENTER120-12

- GET `?projectId=...&mode=regions`는 공식 기관 선택목록의 단일코드 `regions:[{code,name,sourceUrl,historical?}]`와 다중기관 `unselectableGroups`를 반환합니다. `mode=districts&org=...`는 같은 공식 광역에 속한 기초 `districts`만 반환합니다. 주소에서 기관코드를 추정하지 않습니다.
- 목록 근거는 공식 `ordinSc.do`의 `ordinAreaCd`와 `AreaListR.do?keyCd=...`입니다. 확인 시점의 단일코드 옵션19개에는 과거기관·특수기관이 포함되므로 ‘현재 광역19개’라고 설명하지 않습니다. 교육청처럼 여러 코드가 묶인 옵션은 원본명과 코드를 보존하되 하나의 관할로 선택하지 않습니다.
- GET `?projectId=...&mode=review&org=...&sborg=...&regionText=...`는 광역/선택기초의 건축·도시계획/개발행위·경관·환경영향평가4분야 후보를 반환합니다. `sborg`는 선택사항이며 빠지면 기초 검토는 하지 않은 상태입니다. `regionText`는 현재 입력문맥(최대160자)이고 자동 저장하지 않습니다.
- `families`에는 `legalTracks`, `upperLawSources`, `projectFactsToCheck`, `originalSectionsToCheck`, `authoritiesToConfirm`, `candidates`, `searches`, `status`가 있습니다. 후보는 공식 제목·제정기관·판본·원문·조회범위·기관명 대조상태·`appendixStatus:'not_checked'`를 포함합니다. 상위법은 공통 검토근거(`upperLawLinkStatus:'review_basis_only'`)이며 개별 조례의 위임조문을 확인 완료했다는 뜻은 아닙니다.
- 경관법 제27조 개발사업과 제28조 건축물 검토는 별개입니다. 환경영향평가법 제42조의 광역·기초 조례 관계를 확인할 대상으로 표시하며 조례가 두 개 검색됐다는 이유로 절차를 이중 생성하지 않습니다.
- 공식 목록의 광역/기초 코드 관계를 확인하고 요청에 사용합니다. `ordin`에서 `org`만 지정하면 하위 지역이 함께 검색되므로, 광역본청 코드도 공식 목록에서 확인해 별도로 조회합니다. 다른 API의 `lnkOrg.org`와 같은 인자 의미로 혼용하지 않습니다.
- 동일 로그인·사업조회권한·Origin·분당12회 검색제한을 재사용합니다. 외부 요청은 최대24회/30초, 응답당2MiB, 검색당100건×최대2페이지입니다. `hasMore`, `partial_failure`, `failed`를 구분하며 정상0건·관할 미확인·별표 미확인은 비대상이 아닙니다. `appliesToProject`·`notApplicable`은 조회만으로 참으로 바뀌지 않습니다.
- 조회는 인허가 원장·일정·판단·법령 구독을 만들거나 변경하지 않습니다. 원문/별표·필지별 계획결정자료·실제 처리기관·사업 적용은 담당자 추가 확인 대상입니다. [공식 근거 조사](center-20261020-regional-law-review.md)와 실제 서비스 구현·검수 상태를 구분합니다.
