# 법령 수집 완료 근거의 저장 경계 검수

2026-10-29. `LAW130-R1`·`QA130-06`에 연결한 추가 교정입니다. 실제 수집·DB 쓰기·브라우저 실행은 0이며, 이 문서는 전체 376개 수집 완료나 정식 반영을 선언하지 않습니다. 관측된 기존 자동수집은 162개 확인/214개 실패 다음 310개 확인/66개 실패 상태입니다.

실제 `createMaintenanceRuntime`과 엄격한 모형 거래 저장소를 연결한 독립 반례에서, `checkedCount`는 전체 성공인데 `collectionProgress.completed`가 빈 배열인 결과가 성공으로 저장됐습니다. 원문 판본이 없는 축약 기록도 같은 경로를 통과했고 다음 실행이 생략됐습니다. 저장된 현재 날짜만으로 원문 확인을 대신한 문제입니다. 수정 전 독립 2조건 실패와 추가 회귀 34조건 중 4실패를 보존했습니다.

수정은 `server/maintenance-runtime.mjs`의 `validateLawRecovery` 안에만 있습니다. 확인 수가 양수이면 완료 근거와 분리된 수집/재사용 수가 필수입니다. 완료 ID 집합은 **현재 관리 ID에서 실패 ID를 뺀 정확한 집합**이며, 그 개수는 확인 수와 같아야 합니다. 기존 `resumeLawProgress`가 관리범위·공식 법령군·현행/예정 판본·원문 지문·확인일·출처를 확인합니다. 기존 원문/변경이력 보존, 0개/부분 실패, 역할·lease·현재 일자/범위와 거래 원복 검사는 그대로입니다. 다른 법령 서버 3파일과 프런트엔드는 이번 교정으로 바꾸지 않았습니다.

검사 준비도 별도로 정정했습니다.

- 정상 결과를 날짜/ID만으로 축약했던 3개 시험 파일에는 독립 가상 원문 지문·공식 형식 식별자·판본·확인일·체크포인트를 갖춘 정상 자료를 넣었습니다. 기존 실패·보존 단언은 그대로입니다.
- 실제 수집기를 호출하는 시험 2곳의 원문 지문은 임의의 짧은 문자열에서 독립 가상 원문의 SHA-256으로 보완했습니다. 실제 공식 원문 조회라고 주장하지 않습니다.
- 유일한 기대값 대체는 승인된 `LAW130-R1`입니다. 같은 날 같은 범위에서 확인을 마친 B를 다음 slot에 다시 조회한다는 옛 2회 기대를 총 1회로 바꿨습니다. 재사용 1개·신규 수집 0개·시작 0개·A 연기 1개를 추가 대조했습니다. A의 Retry-After·오류·원문 및 다른 작업 보존 단언은 유지했습니다. 옛 실행 기록도 보존했습니다.

최종 현재 소스 회귀는 **32묶음·530조건 통과/실패 0**, 실행 중 소스 변경 0입니다. 수집기 42조건과 runtime 34조건이 포함되며, 이전 524조건에서 늘어난 6개는 새 runtime 반례입니다. 독립 재현 2조건도 통과했으나 기존 집중검사와 중복되는 위험이므로 530에 더하지 않습니다. 백엔드 담당의 별도 읽기 검토도 변경 함수 밖 바이트 동일과 기존 보존 검사를 확인했으며 실행 분모에 더하지 않습니다.

현재 runtime SHA-256은 `adf0f23dcaed7504391087c57f23d03604c8601fd880fb95d042dd6df7d755bc`입니다. 소스 4개, 실패/성공 기록, 시험 준비 정정과 기존 단언 대조는 [검수 메타](review130-law-collection-recovery-verification.json)의 `completionClosure`와 `focused`에 연결했습니다. 과거 524조건 결과는 별도 이력으로 남겼습니다.

실제 배포 후의 제한된 재개 실행과 원문 확인 수/실패 수/완료 판정은 root가 별도로 검수합니다. 모형 530조건의 성공을 실제 자동수집 완료나 `QA130-06` 전수 완료로 올리지 않습니다.
